# Esports Manager — Unity FPS 감독 시뮬레이션

CS 1.6·CS2 같은 클래식 5대5 FPS 팀을 운영하고 **2D 전술 지도 + 선택 선수의 1인칭 화면**으로 관전하는 Unity 프로토타입입니다.

- 저장소: https://github.com/alphamon1114/esportsmanager
- Unity: **6000.6.0f1** (`ProjectSettings/ProjectVersion.txt`)
- 인수인계 갱신: **2026-09-17 / 네임카드 K/D/A·50 피해 어시스트까지**
- 현재 단계: **구매 → 자동 라운드 → 정산·진영 교대 → 맵 승리·결과표**까지 실행됩니다.
- 개발 경로: `C:\unity\esportsmanager`. 다른 컴퓨터에서는 다른 경로를 사용해도 됩니다.

> **먼저 1~2절을 읽으세요.** 현재 코드 기준 요약입니다. 4절의 초기 기획과 5절·9~50절의 날짜별 기록은 변경 당시의 설명이므로, 서로 충돌하면 최신 절의 변경 사항을 따릅니다. 과거의 “미구현”, 검사 개수, 승률 측정값을 현재 상태로 해석하지 마세요.

## 1. 다른 컴퓨터 / 다른 AI에서 시작하기

1. 이 컴퓨터의 변경을 커밋·푸시한 뒤, 집에서는 저장소를 clone하거나 기존 복사본에서 pull합니다. **파일 저장만으로 GitHub나 집 PC에 반영되지는 않습니다.**
2. Unity Hub에서 저장소 루트를 프로젝트로 추가하고 **6000.6.0f1**로 엽니다. 별도 UnityProject 하위 폴더는 없습니다.
3. 가져오기와 컴파일이 끝나면 `Assets/Scenes/Prototype.unity`를 열어 **Play → START MATCH**를 누릅니다.
4. 아군은 **Team Spirit**, 상대는 **Team Falcons**입니다. 초기 배치와 라운드 내 행동은 양 팀 IGL/개별 AI가 결정합니다.
5. 양쪽 선수 카드 또는 미니맵 아이콘을 누르면 해당 선수의 1인칭으로 바뀝니다. 기본 `MAP: ALL PLAYERS`는 상대 위치도 보여주지만 **AI에 적 위치를 공개하지 않습니다.**
6. 라운드 결과 3초 → 초기화·스폰 복귀 → AI 구매 3초 → 다음 라운드를 자동 진행합니다. 맵 종료 시 결과표가 나옵니다.
7. 전략은 대기/타임아웃 중 변경합니다. 진행 중 요청한 타임아웃은 라운드 사이에 적용됩니다. 내부 AI 행동은 기본 숨김, `DEBUG`에서만 확인합니다.

실행에 외부 `Documents/모델링` ZIP이나 예전 작업 폴더는 필요하지 않습니다. 사용할 모델·프리팹·JSON은 저장소의 `Assets`에 있습니다. 무기 모델을 새로 생성할 때만 Blender 생성 도구가 필요합니다.

### 집에서 첫 작업 전에 확인

```powershell
# 저장소 루트에서 실행
 git status --short
 git log -1 --oneline
 powershell -ExecutionPolicy Bypass -File Tools/RunChecks.ps1
```

- 마지막 명령은 Unity에 포함된 Mono를 사용합니다. 정상 종료 문구는 `### suites failed: 0`입니다. 현재 **28개 검사 묶음**이며 수 분 정도 걸립니다.
- Unity 설치 위치가 다르면 `-UnityEditorPath '설치한 Unity의 Editor 폴더'`를 추가합니다. 그래픽/프리팹/HUD는 이 검사로 검증되지 않으므로 실제 Play 화면도 확인하세요.
- 중요한 회귀 검사: **fairness, aim-at-range, behaviour-present**. 교전/행동 수치를 고치고 한 판만 본 뒤 정상이라고 판단하거나 검사 기준을 낮추지 마세요.
- 최신 검증 기록: [전체 검사](docs/measurements/bomb-equipment/checks.txt), [Unity 장비·HUD·자동 경기](docs/measurements/bomb-equipment/unity-checks.txt). 마지막 전체 검사 28개 묶음 실패 0, 이후 단차 C4 회수 보강은 관련 검사와 Unity에서 재확인했습니다. **이번 README 정리에서는 게임 코드를 바꾸거나 검사를 다시 실행하지 않았습니다.**
- 문서 정리 직전 기준 커밋은 `133fd08` (`AIUpgrade`), 작업 트리는 깨끗했습니다. 당시 로컬 `main`과 저장된 `origin/main` 참조는 같았습니다. 실시간 원격 상태를 조회한 것은 아닙니다. 이 README 수정은 별도 커밋·푸시 대상입니다.

### 개발 원칙

- 그래픽은 **더미·로우폴리 우선**입니다. 이미 추가된 CT/T 캐릭터, 총기, 팔 모델은 활용하되 불필요한 고급 아트 작업을 늘리지 않습니다.
- **`BeginDeployment` 이동 테스트 경로를 보존하세요.** HUD의 자동 경기는 `StartMatch`이고, 독립 `BeginRound` 검사는 일부 기존 규칙을 사용합니다. 두 경로가 자동 경기와 완전히 같은 기능을 켠다고 가정하지 마세요.
- AI는 자신의 상태, 맵 구조, 팀 시야/소리/사망 정보로 판단합니다. 관전자 전용 전체 위치나 바닥 총의 숨겨진 잔탄을 AI 판단에 사용하지 않습니다.
- **무빙 스탯은 이동 속도를 바꾸지 않습니다.** 피킹·미스샷 회피 판단과 타이밍에 반영합니다. 칼의 속도 증가는 장비 효과입니다.
- 기존 `.meta` GUID와 사용자 수정 내용을 보존합니다. 열린 Unity 에디터를 강제로 닫지 말고, 별도 검사가 필요하면 임시 복사본을 이용합니다.
- 변경 이유·검증 결과·남은 한계를 이 문서에 함께 갱신합니다.

### 장비 유지에서 혼동하지 말 것

- 과거 “죽어도 장비 유지” 결정 중 **사망 시 가장 강한 총과 킷은 이제 실제로 떨어져 인벤토리에서 빠집니다.** 나머지 장비·크레딧 유지 규칙은 그대로입니다.
- 바닥 무기/킷은 새 라운드에서 정리합니다. 습득한 총은 보유 장비가 되고, 기존 라운드 시작 탄약 보충 정책을 따릅니다.
- 생존 CT의 킷은 유지하고, T로 진영 전환하거나 새 매치를 시작하면 제거합니다. C4는 라운드마다 새로 배정합니다.
- 무기/C4 드롭·전달 메서드는 있지만 **감독 HUD의 수동 드롭 버튼이나 별도 자동 C4 핸드오프 전술은 아직 없습니다.** 총 교환·에이스 지원·C4 회수는 AI 경로에 연결되어 있습니다.

### 현재 한계

- 더미 지형·단순 애니메이션입니다. 점프는 지정 연결 경로, 자유 점프/일반 3D 내비게이션은 없습니다. 소리 거리와 큰 전략 경로는 평면 기준입니다.
- AI는 지형과 정보에 따른 규칙 기반이며 프로 경기 전체를 재현하지 않습니다. CT 약우세는 목표이며 **현재 입체 맵/새 경제/드롭까지 합친 최신 승률은 재측정해야 합니다.** 과거 60판 수치를 그대로 적용하지 마세요.
- CS2의 모든 총기 수치, 거리 감쇠, 다리/복부, 이동 사격, 근접 공격, 자유로운 무기 교환 애니메이션까지 구현한 것은 아닙니다.
- C4 전달은 API, 킷 회수는 근거리 자동 처리입니다. 장비 전달을 위한 별도 전술 UI/자동 C4 분배 정책은 후속 작업입니다.
- 시뮬레이션은 프레임당 최대 0.1초 처리이며 프레임 간격이 다르면 결과가 달라질 수 있습니다. 시드 재현 비교는 같은 시간 간격으로 진행합니다.

### 좌표와 구현 주의점

- 지도 좌표는 대략 0~100 범위이며, `(x, y)`는 월드 `(x, height, 100-y)`로 변환됩니다.
- `Box`로 생성하는 `Wall`과 `Cover`는 이동 장애물 사각형에도 등록됩니다. 지형을 바꿀 때 렌더링과 경로 탐색의 장애물 정의를 함께 유지합니다.
- `DeploymentNavigation`은 장애물을 **두 벌** 씁니다. `Clear`는 캡슐 반지름만큼 부풀린 사각형으로 이동 가능 여부를, `SightClear`는 부풀리지 않은 원본 사각형으로 시야를 판정합니다. 시야에 여유 폭을 적용하면 벽을 따라 스치는 시선이 잘못 끊깁니다. 지형 코드를 고칠 때 이 구분을 유지합니다.
- 탐지는 `SimulateMovement` 안에서 이동 뒤에 갱신되므로, 준비 단계에 서 있을 때나 이동이 끝난 뒤에도 계속 돕니다. Pause 중에는 멈춥니다.
- 아군 여부 판단과 마찬가지로 시야 팀 구분도 `teamId` 기준입니다. 공수 교대와 무관하게 팀 지식이 유지됩니다.
- **한 틱 안의 사격 순서에 주의합니다.** `CombatSystem.Tick`은 두 패스로 나뉩니다. 1패스에서 각자가 틱 안 언제 사격 가능해지는지를 소수점 시간으로 구하고, 2패스에서 그 시간 순으로 처리합니다. 반응 시간과 쿨다운을 0으로 잘라내면 모두가 "틱 시작 시점"에 사격하게 되어, 승부가 배열 순서로 결정됩니다. 개발 중 이 문제로 앞선 선수가 74~80% 이겼습니다.
- `Fire`는 쿨다운을 건드리지 않습니다. 쿨다운은 호출부가 소수점 시간을 담아 설정합니다. 여기서 고정값으로 덮어쓰면 위와 같은 증상이 되돌아옵니다.
- 난수는 반드시 `DeterministicRandom`을 씁니다. 작은 정수 시드에서 초기 출력이 상관되는 생성기(xorshift 등)로 바꾸면 먼저 추첨한 선수가 유리해집니다. `COMBAT_CASE_OK fairness`가 이를 잡습니다.
- 원래 캡슐의 선택 제외 레이어는 8입니다. 현재 모델 렌더링은 캡슐 10, 월드 모델/드롭 11, 선택 선수 월드 모델 12, 1인칭 장비 13을 사용합니다. `CharacterVisuals`·`FirstPersonEquipment`·`GunfireVisuals`의 카메라 마스크를 함께 확인하세요.
- 아군 여부는 CT/T나 배열 순서가 아니라 **teamId `spirit`**로 판단합니다. 상대 명령은 UI에서 숨기는 동시에 `AssignZone`에서도 거부합니다.
- `Prototype` MonoBehaviour와 데이터 클래스는 별도 파일을 유지합니다. 씬을 저장했다가 다시 열어도 컴포넌트가 유지되는지 확인합니다.
- **실행 경로를 구분합니다.** `BeginDeployment`는 예전 이동 테스트, 독립 `BeginRound`는 기존 단판 검사, `StartMatch`는 현재 HUD의 자동 경기입니다. 이동 테스트를 전제로 하는 초기 배치·탐지·교전 항목을 보호하세요. 높이·경제·드롭 등은 자동 경기에서만 활성화되는 부분이 있습니다. 현재 전체 검사 수는 28개 묶음이며 초기 25개 항목과 다른 단위입니다.
- 라운드 한 틱의 순서는 **지난 틱에 정해진 목표대로 이동 → 보고 듣기 → 사격 → 관측한 것으로 다음 목표 결정**입니다. 목표가 한 틱 늦게 반영되는 것은 의도입니다.
- `Route`는 격자 전체 탐색이라 비쌉니다. 목표가 실제로 바뀌었을 때만, 선수당 최대 0.5초에 한 번만 다시 계산합니다. 매 틱 재탐색하도록 바꾸지 않습니다.
- 감시 방향을 "사이트 중심 쪽"으로 두지 않습니다. 수비 배치 좌표가 사이트와 거의 같아서 방향 벡터가 퇴화하고, 수비수가 엉뚱한 곳을 봅니다. 개발 중 이 문제로 수비가 12판 전패했습니다.
- 후퇴에는 `PlayerObjective.disengage`가 필요합니다. 이것이 없으면 적을 본 수비수는 교전 상태로 고정되어 **자리를 뜰 수 없습니다.** `ROUND_CASE_OK behaviour-present`가 후퇴·로테이트·리테이크가 실제로 일어나는지 확인합니다.

## 4. 초기 확정 기획 원문 — 현재 구현 여부는 2절 기준

### 경기와 감독 개입

- 클래식 5대5 폭탄 설치형 FPS. 캐릭터 고유 스킬은 없습니다.
- 기본 9라운드 선승. **8:8이면 듀스**, 2라운드 차이가 나야 맵 승리입니다.
- 정규전 8라운드 종료 후 공수 교대. 연장에서는 매 라운드 교대합니다.
- 타임아웃은 **팀당 맵 전체 2회**, 연장 추가 지급은 없습니다.
- **전략·전술 변경은 타임아웃에만 가능**합니다.
- 매 라운드 시작 전에는 총기·유틸 구매를 지정합니다. **인원 배치는 감독이 아니라 양 팀 IGL이 정합니다** (11절에서 변경).
- 라운드 중에는 선수가 준비된 전술과 자신이 얻은 정보에 따라 판단합니다. 감독의 실시간 이동 명령 기능을 넣지 않습니다.
- 준비된 공수별 전술을 맵 시작 전 설정하는 방식은 앞서 제안되었으며 구체적인 UI·전술 항목은 후속 설계 대상입니다.

### 관전 표시

- 메인은 2D 전술 지도, 보조는 선택 선수의 1인칭 화면입니다.
- 은폐 대기·우회·진입·사격 보류 같은 **내부 행동/판단 텍스트를 표시하지 않습니다.** 움직임과 교전으로 판단을 읽는 것이 의도입니다.
- 향후 행동 관련 표시는 “섬광 투척”, “연막 투척”처럼 **실제로 발생한 라디오 메시지**만 사용합니다. 라디오 시스템은 아직 없습니다.
- 체력·장비 같은 기본 상태 표시는 가능합니다.

### 포지션

- 총기 포지션: **오퍼 / 라이플러**.
- 라이플러 세부 역할: **엔트리 / 앵커·럴커**.
- 앵커·럴커는 같은 분류이며 CT에서는 사이트 유지, T에서는 별동·이동 차단 등을 맡습니다.
- 팀 포지션 인원 구성은 강제하지 않습니다. IGL은 포지션과 별도로 1명 지정합니다.
- 포지션은 사용 가능 총기를 제한하지 않습니다.

### 기본 스탯 (1~100)

| 스탯 | 의도한 영향 |
|---|---|
| 에임 | 조준·명중·반동 제어 등 기본 사격 실력 |
| 유틸 | 투척 위치와 타이밍, 적중 및 차단 효과 |
| 무빙 | 피킹, 좌우 움직임, 정지 사격 전환. 상대 원탭을 피하는 행동 |
| 카리스마 | IGL 지정 시 팀원 추가 스탯 |
| 침착함 | 급발진 감소, 클러치·트레이드 대응 향상, 은폐 상태에서 정보와 멀티킬 기회 판단 |

침착함이 높으면 첫 적을 즉시 쏘지 않고 후속 적을 기다릴 수 있지만, 무조건 오래 기다리는 것은 아닙니다. 발각 위험·아군 지원·기회 소실을 고려해야 합니다. 상대의 숨겨진 인식 상태를 그대로 읽는 대신 관측한 단서로 판단하는 방향입니다.

IGL이 다른 4명의 기본 스탯에 최대 +5를 주고 카리스마에는 중복 보너스를 주지 않는 방식은 **수치 초안**이며 아직 코드에 적용되지 않았습니다. 사망 시 보너스 유지 여부와 계산식도 구현 전에 명시합니다.

### 총기 숙련도와 고정 구매 목록

### 경제 — 초기 기획 기록 (현행 정책은 40·44·45·48절)

짧은 전반 8라운드에 맞춰 **한 라운드 절약 후 구매력을 회복**하도록 설계합니다. 아래 수치는 테스트 시작값입니다.

| 항목 | 개인 크레딧 |
|---|---:|
| 전·후반 시작 | 800 |
| 승리 | 3,200 |
| 첫 패배 | 2,000 |
| 2연패 | 2,500 |
| 3연패 이상 | 3,000 |
| 킬 | 처치자 +200, 총기별 차이 없음 |

- 정규 하프타임에 자금·장비 초기화하는 방향을 채택했습니다.
- 승리하면 패배 보상 단계를 한 단계 낮추는 안입니다. 예: 3연패 → 승리 → 패배 시 2,500. 연속 승리 등 전체 전이표는 경제 구현 때 정의해야 합니다.
- 해체 승리는 승리 보상에 포함하고 별도 해체 보너스는 두지 않는 안입니다.

- 연장 공수 교대 시 생존 장비를 어떻게 처리할지는 미결정입니다. 크레딧 유지와 장비 유지는 같은 결정이 아닙니다.
- 라이플 풀바이 약 4,500~5,000, AWP 풀바이 약 6,000~6,500이 목표 범위이며 개별 가격은 아직 없습니다.

## 6. 검증 방법

현재 전체 실행은 1절의 `Tools/RunChecks.ps1`을 사용합니다(28개 묶음). 아래 개별 검사 명령/이전 검사 개수는 초기부터 누적된 설명입니다. 최근 추가 검사는 `Tools/RunChecks.cs`와 각 변경 절을 확인하세요.

### 자동 검사

프로젝트를 에디터에서 닫은 상태 또는 임시 복사본에서 PowerShell로 실행합니다. 경로는 각 컴퓨터에 맞게 바꿉니다.

```powershell
$unityExe = 'C:\Program Files\Unity\Hub\Editor\6000.6.0f1\Editor\Unity.exe'
$projectPath = 'C:\unity\esportsmanager'
$logPath = Join-Path $env:TEMP 'esportsmanager-deployment-check.log'
& $unityExe -batchmode -nographics -projectPath $projectPath -executeMethod DeploymentChecks.Run -quit -logFile $logPath
```

탐지·교전·라운드 검사도 같은 방식으로 실행합니다.

```powershell
& $unityExe -batchmode -nographics -projectPath $projectPath -executeMethod VisionChecks.Run -quit -logFile $logPath
& $unityExe -batchmode -nographics -projectPath $projectPath -executeMethod CombatChecks.Run -quit -logFile $logPath
& $unityExe -batchmode -nographics -projectPath $projectPath -executeMethod RoundChecks.Run -quit -logFile $logPath
```

실행 프로세스가 끝난 후 로그에서 **`DEPLOYMENT_ALL_OK`**, **`VISION_ALL_OK`**, **`COMBAT_ALL_OK`**, **`ROUND_ALL_OK`**와 정상 종료를 확인합니다. Windows에서 실행 명령만 반환되었다고 검사가 끝났다고 판단하지 않습니다.

현재 검사는 양쪽 시작 진영 × 아군 분산/각 구역 집중 배치 = **8개 구성**을 대상으로 다음을 확인합니다.

- 스피릿 배치 명령 허용 / 팔콘즈 배치 명령 거부.
- 시작 후 배치 명령 잠금.
- 스폰 및 이동 중 벽·엄폐물과의 겹침 없음.
- 제한된 시뮬레이션 시간 안에 이동 완료.
- 이동 중 선수 시점 선택 가능.

최종 아군 제한 변경 후 위 8개 검사는 통과했습니다. 상대는 고정 기본 배치로 검사하며, 현재 검사가 상대의 모든 집중 배치 조합까지 검증하는 것은 아닙니다.

`VisionChecks.Run`은 다음 9개 항목을 확인합니다. 각각 `VISION_CASE_OK <이름>`을 남깁니다.

| 항목 | 확인 내용 |
|---|---|
| frontal | 개활지에서 정면 근거리 대상이 보임 |
| field-of-view | 같은 대상이 등 뒤에 있으면 보이지 않음 |
| peripheral | 반경 5단위 안에서는 시야각을 무시함 |
| range | 최대 사거리를 넘으면 시선이 통해도 보이지 않음 |
| obstruction | 지형을 통과하는 시선이 차단됨. 검사 지점은 실행 시 맵에서 직접 찾음 |
| recognition | 인지 시간 전에는 접촉으로 등록되지 않고, 노출이 쌓이면 등록됨 |
| memory | 시야가 끊기면 `visible=false`, 마지막 목격 위치 유지, 6초 후 소멸 |
| information-separation | 스폰 직후 양 팀 모두 상대 위치를 하나도 모름 |
| determinism | 같은 입력 두 번이 같은 접촉 기록을 만듦. 접촉이 실제로 발생하는 시나리오로 확인 |

마지막에 `VISION_ZONE_SIGHT` 9줄이 **진단 정보**로 출력됩니다. 단언이 아니므로 검사를 실패시키지 않습니다. 현재 값은 `VISION_ZONE_SIGHT_PAIRS 0 of 9`입니다.

`CombatChecks.Run`은 다음 8개 항목을 확인합니다.

| 항목 | 확인 내용 |
|---|---|
| resolution | 개활지 대치가 제한 시간 안에 한쪽 사망으로 끝남 |
| determinism | 같은 시드가 체력 변화까지 같은 라운드를 재생 |
| seed-sensitivity | 시드를 바꾸면 결과가 달라짐. 난수가 실제로 소비되는지 확인 |
| obstruction | 벽 너머로는 사격도 피해도 없음 |
| range | 사거리 밖에서는 시선이 통해도 사격 없음 |
| no-contact-no-damage | 접촉이 없는 정상 배치 라운드에서 사격 0, 피해 0 |
| fairness | 동일 실력 200판의 선행 선수 승률이 42~58% |
| aim-at-range | 장거리에서 에임 98이 에임 72를 58% 넘게 이김 |

`fairness`와 `aim-at-range`는 **통계 검사**입니다. 시드 집합이 고정이라 결과는 결정적이며 무작위로 실패하지 않습니다. 두 항목은 개발 중 실제로 발생했던 결함 — 배열 순서가 승부를 결정하던 문제와, 오차각이 너무 작아 에임이 무의미하던 문제 — 을 고정하기 위한 것입니다. 수치 조정으로 이 검사가 깨지면 조정이 잘못된 것인지 먼저 의심합니다.

참고로 한 판을 눈으로만 보면 두 결함 모두 정상으로 보입니다. 교전 관련 수치를 바꿀 때는 단판 확인이 아니라 이 통계 검사를 신뢰합니다.

`RoundChecks.Run`은 다음 8개 항목을 확인합니다.

| 항목 | 확인 내용 |
|---|---|
| termination | 12판 전부 제한 시간 안에 정해진 사유로 종료. 매 틱 폭탄 불변식 확인 |
| determinism | 같은 시드가 같은 라운드를 재생 |
| outcome-variety | 시드에 따라 종료 사유가 갈림. 라운드가 정해진 각본이 아닌지 확인 |
| behaviour-present | 설치·후퇴·로테이트·리테이크가 **실제로 발생**함 |
| observed-information-only | 시야와 청각을 끈 수비는 사이트 위에 적이 서 있어도 반응하지 않음 |
| bomb-explodes | 아무도 오지 않는 폭탄은 40초 후 폭발 |
| bomb-defused | 방해 없는 폭탄은 10초 만에 해체 |

`behaviour-present`는 특히 중요합니다. 후퇴·로테이트·리테이크는 개발 중 **각각 한 번씩 조용히 사라진 적이 있고**, 그래도 라운드는 정상적으로 끝나고 겉보기에 그럴듯했습니다. 행동 규칙을 고칠 때 이 검사를 먼저 봅니다.

`observed-information-only`는 4절의 정보 분리 원칙을 코드로 고정한 것입니다. 판단 로직에서 상대의 실제 좌표를 읽으면 이 검사가 깨집니다.

### Unity 없이 빠르게 돌리기

대역 클래스와 실행 진입점이 `Tools/`에 들어 있습니다. 7개 suite 전부를 1분 남짓에 돌립니다.

```bash
mcs -out:/tmp/checks.exe -nowarn:0169,0414,0649,0108,0219,0660,0661 \
    Tools/HeadlessStub.cs Tools/RunChecks.cs Assets/Scripts/*.cs Assets/Editor/*.cs
mono /tmp/checks.exe
```

마지막 줄이 `### suites failed: 0`이면 통과입니다. 자세한 내용과 새 Unity API를 쓸 때의 대처는 `Tools/README.md`를 봅니다.

**이 방식은 로직만 검증합니다.** 렌더링, 에셋 임포트, 씬 직렬화, `.meta` 처리를 보지 않으므로 커밋 전에는 위의 Unity 배치 검사를 돌립니다.

`PrototypeSetup.CreateScene`은 **씬을 재생성하는 도구**입니다. 기존 씬을 덮어쓸 수 있으므로 커스텀 편집이 있는 작업 씬에는 무심코 실행하지 않습니다. 실행 시 `FPS_PROTOTYPE_SMOKE_OK`, `FPS_SCENE_RELOAD_OK`가 성공 표시입니다.

### 수동 확인

- Play 시작 시 두 팀이 각자 스폰에 모이는지 확인합니다.
- 스피릿을 선택했을 때만 Initial zone이 나오는지 확인합니다.
- 팔콘즈 선택 시 배치 버튼·예정 배치 인원 수가 노출되지 않는지 확인합니다.
- 공수를 바꿔도 스피릿만 조작 가능한지 확인합니다.
- 이동 중 2D와 1인칭 위치가 일치하는지, Pause / Resume과 Reset이 작동하는지 확인합니다.
- 상단 표시가 `SETUP` → `LIVE` → (설치 시) `BOMB DOWN at A/B` → `ROUND OVER`로 진행되는지 확인합니다.
- **Fog of war ON에서 지도에 팔콘즈 마커가 보이지 않다가, 스피릿이 탐지하면 나타나는지** 확인합니다. 시야가 끊긴 뒤에는 마지막 목격 위치에 `?`가 붙습니다.

## 13. 후퇴 판단 복구와 소모품 재지급 (2026-09-15)

12절 작업이 들어온 뒤 `ROUND_CASE_OK behaviour-present`가 깨져 있었습니다. 60판을 돌려도 **수비수가 사이트를 포기하는 일이 한 번도 일어나지 않았습니다.**

- 원인: 후퇴 판단이 "지금 보이는 적 수 대 사이트 근처 아군 수"뿐이었습니다. T가 한 명씩 들어오게 바뀌면서 수비수가 무리를 볼 일이 사라져, 사이트가 무너지는 동안에도 열세로 읽히지 않았습니다. 살아 있는 수비수가 있는 동안 `본 적 − 아군`이 한 번도 1 이상으로 올라가지 않았습니다.
- 수정: **사이트에서 최근 12초 안에 쓰러진 아군 수**를 판단에 더했습니다. `본 적 + 잃은 아군 > 사이트 근처 아군 + 여유`. 동료가 여기서 죽었다는 것도 팀이 실제로 관측한 사실이므로 정보 분리 원칙을 지킵니다. 개별 진입은 그대로 둡니다.
- 소모품은 **라운드 시작마다 다시 지급**합니다. `PlayerMatchState.RestockUtility()`가 섬광·연막만 채우고 무기와 크레딧은 건드리지 않습니다. 그 전에는 소비만 되고 보급이 없어 4라운드 뒤에 30개 중 18개만 남았고, 경제가 없으니 재구매 경로도 없었습니다.
- `RoundResetChecks`의 장비 단언을 그에 맞게 고쳤습니다. 크레딧과 **소모품이 아닌 장비**가 유지되는지를 보고, 라운드 시작 시 섬광·연막이 다시 있는지도 함께 확인합니다.
- `Tools/`에 헤드리스 검사 도구를 넣었습니다. 9절에서 "저장소에서 찾지 못함"으로 남은 항목입니다.

남은 유력한 가설은 배치 구조입니다. IGL이 수비를 B/중앙/A 세 곳에 나누는 동안 공격은 한 사이트로 전원 수렴하고, 중앙 병력은 개별 진입 탓에 한 명씩 도착해 이미 자리 잡은 인원과 싸웁니다. **확인되지 않은 가설이며 밸런싱은 아직 착수하지 않았습니다.**

## 14. 수비 각 잡기, 엄폐, 트레이드, 진입 유틸 (2026-09-15)

사용자 보고: **"CT가 사이트에 도착한 뒤 계속 엉뚱한 방향을 보고 있어서 어이없이 죽는다."**

### 측정으로 확인한 것

30판 137명의 수비수 사망에 대해, 죽는 순간 자신의 조준 방향과 자신을 쏜 적 방향 사이의 각도를 쟀습니다.

| 각도 | 수정 전 | 수정 후 |
|---|---:|---:|
| 0~50° (보고 있던 방향) | 47% | **63%** |
| 50~90° | 13% | 8% |
| 90~140° (측면·등 뒤) | 25% | 23% |
| 140~180° (완전히 등 뒤) | 15% | **7%** |

같은 기준으로 공격수는 수정 전에도 67%가 정면에서 죽었습니다. 수비만 겪던 문제입니다.

### 원인

- 감시 방향이 사이트마다 **한 방향**만 가리켰습니다. A 사이트는 진입로가 셋인데 전원이 같은 쪽을 봤습니다.
- 12절의 무작위 순찰이 0.6~1.3초마다 2.5단위 안에 새 목적지를 줬습니다. **이동 중인 선수는 진행 방향을 보므로**, 수비수는 대부분의 시간을 아무것도 없는 쪽을 향한 채 걸어다녔습니다.

### 구현

- **진입로 입구 도출.** 각 T 라인에서 사이트까지 경로를 뽑고, 사이트 반경을 벗어나는 마지막 지점을 입구로 삼습니다. 하드코딩이 아니라 맵에서 나오므로 지형을 바꿔도 따라옵니다. 현재 A 3곳, B 2곳입니다.
- **피킹·엄폐 지점 쌍.** 입구마다 사이트 근처에서 그 입구가 **보이는** 자리(피킹)와, 거기서 3단위 떨어진 **안 보이는** 자리(엄폐)를 찾습니다. 입구에 가깝고 뒤로 뺄 곳이 있는 자리를 우선합니다.
- **수비 분산.** 같은 사이트를 맡은 수비수들은 서로 다른 입구를 맡습니다. 순위 기준이라 결정적입니다.
- **엄폐 전환.** 재장전 중이거나 섬광에 눈이 멀었거나 체력 40 미만이면 엄폐 지점으로 물러났다가 바로 복귀합니다. 감시 방향은 양쪽에서 같습니다.
- **무작위 순찰 제거.** 소리를 듣고 그쪽으로 3단위 다가가는 수색은 남겼습니다.
- **트레이드.** 공격수는 6초 안에 동료가 쓰러진 자리가 목표 사이트 근처에 있으면, 빈 거점 대신 그 자리로 받아칩니다. 그 각을 이긴 수비수가 아직 거기 조준하고 있기 때문입니다. 폭탄 운반자는 제외합니다.
- **진입 유틸.** 공격 목표(`PushSite`/`PlantBomb`/`Trade`)일 때는 적이 **보이지 않으면 연막**으로 알려진 수비 각을 끊고, **보이면 섬광**을 칩니다. 이전에는 체력이 낮거나 후퇴할 때만 던져서 사실상 수비 전용이었습니다.

### 검사

`RoundChecks`에 두 항목을 더했습니다.

| 항목 | 확인 내용 |
|---|---|
| defender-facing | 20판 수비 사망 중 **자신이 보던 방향에서 죽은 비율이 55% 이상**. 현재 62% |
| cover-trade-entry-utility | 엄폐 전환·트레이드·진입 유틸이 실제로 발생 |

`defender-facing`은 통계 검사입니다. 시드 집합이 고정이라 결정적입니다. 이 문제는 **서로 무관한 변경 두 번에서 각각 다시 나타났고**(감시 벡터 퇴화, 순찰 도입) 두 번 모두 라운드는 정상 종료되고 다른 검사도 전부 통과했습니다. 배치·감시·이동 쪽을 건드린 뒤에는 이 수치를 먼저 봅니다.

### 남은 한계

- A 사이트는 진입로가 3곳인데 수비가 1~2명일 때가 많아 **한 곳은 비어 있습니다.** 측면 사망 23%가 대부분 여기서 나옵니다. 유틸이나 로테이션으로 메우는 판단이 없습니다.
- 엄폐는 위치일 뿐입니다. 부분 엄폐·웅크리기·린이 없어 엄폐 지점에서는 **아예 보이지 않고** 피킹 지점에서는 **완전히 보입니다.**
- 피킹이 상황 판단이 아니라 상태 조건(재장전·섬광·저체력)으로만 일어납니다. 유리할 때 먼저 나가서 각을 따는 행동은 없습니다.
- 트레이드가 동료가 쓰러진 좌표로 가는 것뿐입니다. 누가 어느 각에서 쐈는지는 쓰지 않습니다.

### 밸런스

60판 기준 수비 27% → **30%**, 폭탄 설치 57% → 47%, 평균 39.3초. 여전히 공격이 유리하고 CT 소폭 우세 요구와 반대입니다. 13절의 가설(수비는 세 곳에 나뉘고 공격은 한 곳에 모인다)은 그대로 남아 있습니다. 밸런싱은 아직 착수하지 않았습니다.

## 15. 팀 정보 공유와 교전 성립 (2026-09-15)

사용자 보고: **"서로 시야에 들어왔는데도 교전하지 않는다. 그리고 팀원끼리 소통하지 않는다. 팀이 얻는 모든 시야·소리 정보를 공유하되, 죽으면 지금까지 얻은 정보만 남기고 더는 얻지 못해야 한다."**

### 측정으로 확인한 것

15판 동안, 적 두 명 사이에 **기하학적으로 시선이 통하고 55단위 안에 있는** 모든 조합을 매 틱 세고, 실제로 보이지 않았다면 원인을 분류했습니다.

| 항목 | 수정 전 | 수정 후 |
|---|---:|---:|
| 실제로 보임 | 19% | **33%** |
| 연막에 막힘 | **36%** | 16% |
| 시야각 밖 | 23% | 22% |
| 섬광에 눈이 멈 | 8% | 7% |
| 인지 시간 미달 | 13% | 21% |
| 마주 본 두 명이 **서로 아무도 못 봄** | 72% | **57%** |

연막 36%가 가장 큰 원인이었고, 이건 14절에서 제가 "진입 시 적이 안 보이면 연막"으로 바꾼 것이 맵을 덮은 결과였습니다.

### 구현

**팀 정보 공유**

- 소리 기억이 **개인별에서 팀 단위**로 바뀌었습니다. `MatchSounds`가 팀마다 최근 단서 목록을 들고 있고, 살아 있는 선수는 그중 자기에게 가장 가까운 것을 봅니다. 한 명이 들으면 팀 전체가 압니다.
- 시야 정보는 원래부터 팀 공유였습니다(`VisionSystem`의 팀 지식).
- **사망자는 더 이상 정보를 수집하지 않습니다.** 관찰자로도 청취자로도 제외됩니다. 이미 팀에 넘긴 단서는 그대로 남고, 다른 단서와 똑같이 시간이 지나면(소리 4초, 시야 6초) 낡아서 사라집니다. CS2에서 죽은 선수가 관전은 해도 콜을 못 하는 것과 같은 모양입니다.

**이동 중 시야 확보**

- 이동 중인 선수는 진행 방향만 보고 있었습니다. 교차하는 경로로 지나가는 두 명은 서로를 **볼 기회 자체가 없었습니다.**
- 이제 이동 중에도 **팀이 아는 접촉** 중 진행 방향 기준 좌우 90도 안에 있는 가장 가까운 것을 봅니다. 뒤로는 돌지 않으므로 달리면서 등 뒤를 쏘는 일은 여전히 없습니다.
- 아는 접촉이 없으면 진행 방향 좌우 45도를 2.6초 주기로 **훑습니다.** 아무도 안 보면 아무도 못 알아채는 닭과 달걀 문제를 끊기 위한 것입니다.
- 주변시야 반경을 5 → 10단위로 올렸습니다.
- 후퇴 중(`disengage`)인 선수는 제외합니다. 물러날 때는 앞만 봅니다.

**연막 사용 규칙**

- 연막은 **후퇴 중이거나, 체력 45 미만이거나, 대상이 20단위보다 멀 때만** 던집니다. 근거리 진입은 섬광입니다. 연막을 자기 진입로에 치는 것을 막습니다.
- 이미 8단위 안에 아군 연막이 있으면 던지지 않습니다. 이전에는 진입하는 다섯 명이 같은 자리에 각자 하나씩 던졌습니다.
- 지속 시간 12초 → 9초.

### 검사 변경

기존 검사 두 개가 이번 변경을 정확히 잡았고, 둘 다 **검사 쪽 전제가 낡은 것**이라 검사를 고쳤습니다.

- `VisionChecks`의 시야각 검사가 10단위 거리를 쓰고 있었는데, 주변시야 반경이 10이 되면서 시야각이 적용되지 않는 거리가 됐습니다. 20단위로 옮기고, 앞으로 이 값이 바뀌어도 알 수 있도록 "시야각 검사는 주변시야 밖에서 해야 한다"는 단언을 넣었습니다.
- `AutonomyChecks`의 소리 검사가 "멀리 있는 선수는 못 듣는다"를 전제했는데, 팀 공유가 되면서 틀린 전제가 됐습니다. 이제 **범위 안에 아무도 없는 팀은 못 듣는다**와 **멀리 있는 팀원도 공유받아 안다**를 함께 확인합니다.

새 검사 두 개를 넣었습니다.

| 검사 | 항목 | 확인 내용 |
|---|---|---|
| `RoundChecks` | engagement | 시선이 통하는 조합 중 **25% 이상이 실제로 보여야** 하고, **연막에 막힌 비율은 25% 미만**. 현재 32% / 16% |
| `AutonomyChecks` | dead-players-keep... | 죽은 선수가 새 정보를 못 얻고, 이미 넘긴 단서는 남으며, 시간이 지나면 낡아 사라짐 |

`engagement`도 통계 검사입니다. 이 문제는 서로 무관한 변경 두 번에서 각각 생겼고(이동 방향에 조준 고정, 소리마다 연막 투척) 두 번 모두 라운드는 정상 종료되고 다른 검사는 전부 통과했습니다. 시야·유틸·이동 쪽을 건드린 뒤에는 이 수치를 먼저 봅니다.

### 아직 안 한 것

- **이번 변경 후 승률을 재측정하지 않았습니다.** 14절의 "수비 30%"는 이 변경 이전 값이라 현재 상태를 나타내지 않습니다. 다음 작업 때 60판 측정을 먼저 돌립니다.
- 주변시야 10단위와 시야 훑기는 "고개를 따로 못 돌린다"는 제약을 우회하는 근사입니다. 제대로 하려면 몸 방향과 시선 방향을 분리해야 합니다.
- 소리 단서가 종류를 구분하지 않고 "가장 가까운 것" 하나만 쓰입니다. 총성과 발소리의 우선순위 차이가 없습니다.
- 섬광이 여전히 아군을 가리지 않습니다.
- 연막이 원형 한 겹이라, 실제처럼 좁은 통로를 정확히 막는 배치가 아닙니다.

- 착지 이벤트는 유틸 fuse가 처음 0을 지날 때 발생합니다. 실제 청취 범위 안의 살아 있는 팀원이 있어야 팀에 공유합니다. 동일 착지 이벤트는 팀별 한 번만 집계합니다. 투척 시작 소리·아군 유틸은 수비 공격 징후에 포함하지 않습니다.
- 착지 좌표는 소리 추정 구역으로 저장하고, 그 좌표를 투척자의 위치로 VisionSystem에 보고하지 않습니다. 기존 소리 종류와 발생 카운터는 유지하며 착지는 별도 내부 이벤트입니다. 현재 착지/폭발은 동일 시점의 단순 모델입니다.
- 소리 징후만 있으면 백업 계산용 압력을 2로 설정합니다. 실제 인원수를 추정해 더하지 않습니다. 기존 반대 사이트 최소 경계, 교전 중 지원 제외, 정보 단절 뒤 복귀 규칙을 그대로 적용합니다. 소리 정보 객체는 라운드마다 새로 만들고 Director.Reset에서도 연결을 해제합니다.
- 신규 집중 검사 통과: 발소리 2개 미발동/3개 발동, 한 자리 반복음 미발동, 한 착지의 여러 청취자 중복 방지, 착지 2회 백업, 시간 만료, 아군 유틸·투척 시작 제외, 사망자 청취 금지, 착지로 투척자 위치 노출 금지. 기존 BackupChecks에 포함했습니다.

## 24. 누적 반동과 초탄 이후 스프레이/회피 선택 (2026-09-16, Codex)

- 연사 시 총기별 반동을 누적합니다. 권총 0.3도, 데저트이글 0.8도, SMG 0.12도, 소총 0.18도, AWP 1도이며 최대 누적 3도입니다. 발사를 0.25초 쉬면 초당 2도씩 회복합니다. 초기 조정값이며 실제 CS2 반동 패턴 복제는 아닙니다.
- 에임이 높을수록 반동 보정이 좋아집니다. 탄착에 남는 반동은 누적량 × (1 - 0.8 × 에임/100)입니다. 상향 반동과 연사 순서에 따른 좌우 변위를 실제 머리/몸통 탄착 계산에 더합니다. 단순 명중률 감점은 아닙니다.
- 초탄 후 상대가 살아 있으면 스프레이 또는 회피 후 재조준을 선택합니다. 빗나감과 비치명 몸통 명중 모두 포함하며, 처치했다면 후속 회피를 요청하지 않습니다. 연사 묶음 동안 선택을 유지하고 충분히 쉬어 반동이 회복되면 새로 선택합니다.
- 스프레이 선택 확률 = clamp(0.5 + (에임 - 무빙)/150, 0.15, 0.85). 같은 값이면 50:50이며 에임 우세는 스프레이, 무빙 우세는 회피 쪽으로 기웁니다. 판단 난수는 별도 선수별 스트림으로 관리합니다. 발사 간격 0.4초 이상인 총(AWP)은 스프레이 대신 회피/재조준을 선택합니다.
- 회피 선택은 기존 PeekMovement에 확정 요청을 보내므로 이전 미스샷 확률 추첨을 또 하지 않습니다. 기존 미스 이벤트 자체는 유지하지만 실제 라운드의 OnMiss 연결은 제거했습니다. 회피 선택 후 0.65초 사격을 중단하며, 실제 이동/정지 준비가 더 오래 걸리면 그동안도 사격하지 않습니다. 다음 발사는 머리 조준을 시도하되 탄퍼짐과 부위 판정 때문에 명중·헤드샷을 보장하지 않습니다.
- 이동속도는 변경하지 않았습니다. 이동 공간이 없거나 설치·해제 등 우선 임무가 있으면 실제 좌우 이동은 못 할 수 있으며, 그 경우에도 사격을 쉬고 재조준합니다. 스프레이 선택도 강제 엄폐·후퇴·장전보다 우선하지 않습니다.
- 머리/몸통 피해 검사는 탄퍼짐과 반동을 0으로 두고 피해 자체를 분리 검증하도록 갱신했습니다. 신규 RecoilChecks는 실제 탄착까지 검증합니다. 40발·거리50·기본 탄퍼짐0인 통제 조건에서 무반동 40명중, 반동+에임0 5명중, 반동+에임100 30명중이었습니다. 실제 경기 명중률 예측값은 아닙니다.
- 동일 100개 시드의 비치명 초탄에서 에임100/무빙0은 스프레이 84회, 에임0/무빙100은 19회 선택했습니다. 반동 누적/상한/휴지 회복/초기화, 재조준 중 사격 중지, 치명타 후 불필요한 후속 행동 없음도 통과했습니다. 표준 실행기에 추가하여 검사 묶음은 총 10개입니다.
- 최종 검증: 기존 9개 검사 묶음 전체 통과, 신규 RecoilChecks와 갱신된 HitZoneChecks 별도 통과. fairness 51.0%, aim-at-range 77.0%, behaviour-present 통과, defender-facing 68%, engagement 40% / 연막 차단 8%. Unity 내장 Mono + HeadlessStub 검증이며 이번 변경 후 화면 캡처·진영 승률 측정은 하지 않았습니다. 카메라 흔들림/총기 애니메이션은 추가하지 않았고 반동은 탄착 계산에 적용됩니다.

## 26. 아군 연속 사망 구역에 조심스럽게 백업 (2026-09-16, Codex)

- 기존에는 사망 기록이 해당 사이트 수비수의 후퇴 판단에만 쓰였고, 다른 수비수의 백업에는 쓰이지 않았습니다. 이제 최근 12초(`lossMemory`) 안에 아군 2명이 서로 14단위 이내에서 사망하면 위험 신호로 판단합니다.
- 사이트 밖 중앙/통로에서도 적용합니다. 지원 인원 배정에는 가장 가까운 사이트 구역을 이용하지만, 이동 목적지는 실제 아군 사망 지점입니다. 사망 위치의 평균점은 벽 안일 수 있으므로 사용하지 않습니다. 구역 판정은 거리 기반 근사여서 벽으로 분리된 가까운 통로를 완전히 구분하지는 않습니다.
- 사망자는 추가 시야 정보를 제공하지 않습니다. 팀이 아는 아군 사망 위치/시간만 사용하며, 적 위치를 알아냈다고 기록하지 않습니다. 기존 지원자 거리 선정·교전 중 제외·반대 사이트 최소 경계 규칙을 유지합니다.
- 지원 목표에 `cautious`를 지정합니다. 위험 지점까지 20단위 미만이면 일반 걷기(2.4단위/초)로 접근하고 달리기 발소리를 내지 않습니다. 먼 거리는 기존 이동 속도를 유지하며, 이동속도에 무빙 스탯을 반영하지 않습니다. 적을 발견하면 기존 시야·교전 처리가 적용됩니다.
- 도착 후 그 구역을 경계합니다. 위험 기억이 만료되면 기존 지원 유지/해제 규칙을 따릅니다. 폭탄 설치 후에는 기존 리테이크/해제 명령을 우선합니다. 새 라운드는 기존 사망 기록 초기화로 위험 정보도 지웁니다.
- 확장 BackupChecks 집중 검사 통과: 적 시야 0에서도 아군 2명 사망 후 출발, 한 명 사망은 미발동, 중앙 사망 구역을 실제 목적지로 사용, 반대 사이트 경계 유지, 근처 걷기와 무소음, 먼 거리 정상 이동, 기억 만료 및 다음 라운드 초기화.
- 최종 검증: 기존 11개 검사 묶음 전체 통과, 사망 구역 검사를 추가한 BackupChecks 별도 통과. fairness 51%, aim-at-range 77%, behaviour-present 통과, defender-facing 73%, engagement 36% / 연막 차단 10%. Unity 내장 Mono + HeadlessStub로 검증했으며 화면 체감과 진영 승률은 이번 변경 후 별도 측정하지 않았습니다.

## 27. 총기별 고정 스프레이 패턴과 불완전 보정 (2026-09-17, Codex)

- **직접 작성한 게임용 근사 패턴이며 CS2에서 추출·측정한 정확한 패턴은 아닙니다.** 권총과 AWP도 프로필을 갖지만 느린 발사 간격 때문에 반동 회복의 영향을 많이 받습니다. 일반적인 정확도 회복의 구분은 Valve의 [Second Shot 설명](https://blog.counter-strike.net/second-shot/)을 참고했으며, 해당 과거 글을 현재 CS2 수치의 근거로 사용하지 않습니다.
- 실제 탄착 = 조준 방향 + 보정 후 패턴 + 보정 실행 오차 + 기존 무기 탄퍼짐입니다. 패턴은 난수와 무관하게 동일하지만 보정 실행 오차는 별도의 선수별 시드 스트림에서 생성됩니다. 같은 시드는 재현되며 다른 시드에서 미세한 탄착 차이가 납니다.

- [AK 패턴·에임별 보정 비교](docs/measurements/spray-pattern-preview.svg): 세 패널은 같은 축척이며 기본 탄퍼짐을 제외해 고정 곡선과 보정 잔여량만 보여줍니다. 실제 게임의 탄착은 여기에 무기 탄퍼짐이 추가됩니다.

## 29. 지속 연사 반동이 약했던 문제 보정 (2026-09-17, Codex)

## 30. 이동 방향과 조준 방향 분리 (2026-09-17, Codex)

- 원인: 라운드의 StepRoute가 매 프레임 이동 방향으로 배우를 회전시키고, AimWhileMoving이 다시 정보 방향으로 회전시켰습니다. 이동 기준 뒤쪽 90도 밖의 정보는 버렸고, 이탈 중에는 조준 갱신도 생략해 후퇴할 때 적에게 등을 보였습니다.
- 라운드 경로 이동은 이제 위치만 갱신합니다. MovementAim은 직접 보이는 적, 팀이 본 적, 최근 기억·소리의 순서와 거리를 고려해 월드 좌표를 조준합니다. 옆걸음·후진·엄폐 복귀 중에도 해당 지점을 바라보며 회전 속도 제한을 유지합니다. 상대의 실제 좌표나 숨은 생존 상태를 추가로 읽지 않습니다. 소리는 기존의 거친 추정 좌표를 사용합니다.
- 비슷한 정보 사이에서 매 프레임 조준 대상이 바뀌지 않도록 기존 대상에 소폭 우선권을 줍니다. 2.5초보다 오래된 정보는 이동 조준에서 제외하고, 정보가 없으면 다음 경로 모퉁이나 수비 경계 방향을 봅니다. 현재 시선에 매 프레임 사인파를 더하던 강제 좌우 훑기는 제거했습니다. 새 라운드에는 조준 선택기를 새로 만듭니다.
- 경로 이동 중 arrived=true가 남아 정지 정확도로 발사하던 불일치도 수정했습니다. 실제 위치가 바뀐 프레임에는 사격하지 않고, 적을 발견하면 다음 이동 판단에서 멈춘 뒤 기존 교전으로 들어갑니다. 엄폐 복귀·이탈은 적을 보더라도 우선 이동합니다. 기존 피킹의 이동/정지/재조준 흐름은 유지하며 이동 사격의 별도 정확도 모델은 추가하지 않았습니다.
- 일반 이동·걷기·피킹 속도 및 무빙 스탯 규칙은 유지합니다. 기존 BeginDeployment 이동 테스트에서는 이전처럼 경로를 향해 회전합니다. 실제 배우의 조준 방향을 시야 판정과 1인칭 카메라가 함께 사용합니다.
- 신규 MovementAimChecks 집중 검사 통과: 횡이동/후진의 같은 월드 지점 조준, 숨은 적 이동에 반응하지 않음, 기억 만료, 비슷한 정보 사이의 시선 안정성, 실제 경로 이동이 시선을 덮어쓰지 않음, 후퇴 중 적 방향 유지, 다음 라운드 초기화. 별도 실제 라운드 검사에서 발사 23회 모두 위치 이동이 없는 프레임임을 확인했습니다. 표준 검사 실행기는 총 15개 묶음입니다.
- 최종 검증: 15개 검사 묶음 전체와 정지 후 사격을 추가한 MovementAimChecks 별도 검사 통과. fairness 51%, aim-at-range 76.5%, behaviour-present 통과. defender-facing은 이전 74%에서 90%, engagement는 36%, 연막으로 가려진 비율은 24%였습니다(기존 검사 기준 통과). Unity 내장 Mono + HeadlessStub로 검증했으며, 이번 변경 후 Unity 에디터의 시각적 움직임은 별도 확인하지 않았습니다.

## 31. 목적에 따른 연막·섬광 사용 판단 (2026-09-17, Codex)

- 기존 판단은 보이는 적 또는 아무 소리만 있으면 거리·체력으로 유틸 종류를 골랐습니다. 폭탄 비프음도 포함됐고, 적 전멸 후 남은 소리와 투척자·아군의 섬광 노출을 검사하지 않았습니다. UtilityDecisions로 판단을 분리했습니다.
- **공통 조건:** 상대 생존자가 있어야 하며, 최근 2.5초 이내 비익명 시야 정보 또는 1.2초 이내 적 행동 소리가 필요합니다. 비프음과 단순 유틸 투척 소리는 단독 발동 근거에서 제외합니다. 죽은 선수의 시야 정보, 정보가 없는 적의 실제 좌표는 사용하지 않습니다. 사망·실명·재장전·설치·해제·폭탄 회수 중에는 새 투척을 하지 않습니다. 적 전멸 뒤 폭탄만 남아 라운드가 계속되는 경우에도 유틸을 아낍니다.
- **연막:** 수비 위치에서 다수 진입(근처 적 둘 이상 목격, 다수 발소리·착탄 신호) 또는 체력 45 미만의 위급 상황에 접근 방향을 차단하거나, 후퇴 위치를 가리거나, 진입/리테이크/트레이드 이동 때 18단위보다 먼 측면 적 사선을 가리는 용도로 사용합니다. 알려진 위험 방향의 6~14단위 앞을 후보로 삼고 그 사선을 실제로 가리는지 확인합니다. 공간 진입용 연막은 아군 직선 이동 경로에 겹치면 거절합니다. 수비 차단과 후퇴 엄폐는 목적상 차단을 허용합니다. 가까운 기존/비행 중 연막과 중복하지 않으며, 같은 팀 연막이 24단위 이내 구역을 이미 가리고 있으면 추가 투척을 보류합니다.
- **섬광:** PushSite·Retake·Trade 임무에서 예상 적 위치를 무력화해 진입을 돕는 경우만 던집니다. 가까운 소리가 들린 수비수가 무조건 섬광을 던지지는 않습니다. 투척자 기준 약 20.5/22/24단위 앞에서 적 추정점과 12단위 이내인 착탄점을 찾고, 지형·직선 투척 경로·적 추정점까지의 효과 경로를 확인합니다. 이전 14단위 착탄은 섬광 반경 15 안에 투척자 자신이 남는 문제가 있었습니다.
- 투척 오차 적용 **후** 투척자와 살아 있는 모든 아군의 위험을 검사합니다. 착탄점에서 20.1단위 이내(효과 반경 15 + 1초 신관 동안의 이동 여유)이고 지형으로 가려지지 않은 아군이 있으면 투척하지 않습니다. 목표 뒤의 아군도 검사하고, 같은 곳의 대기 중 섬광은 중복하지 않습니다. 아군에게 섬광 면역을 부여한 것은 아닙니다. 신관 중 코너를 돌아 노출되는 등 투척 시점과 달라진 상황까지 완전히 예측하지는 않습니다.
- 벽 바운드·곡사·팀원에게 고개 돌리기를 명령하는 협동 팝플래시는 이번 범위에 없습니다. 안전한 직선 착탄점을 찾지 못하면 유틸을 보존합니다. 내부 행동 라벨은 추가하지 않았으며 기존 유틸 시각 효과와 라디오를 사용합니다.
- 신규 UtilityDecisionChecks 집중 검사 통과: 수비 길목/후퇴/측면 엄폐, 적에게 효과가 있는 안전한 진입 섬광, 아군 앞뒤 위험, 아군 정면 진입로 연막 거절, 적 전멸, 오래된 소리/비프/단순 투척음/무정보 거절, 폭탄 작업 우선, 중복 섬광, 벽, 낮은 유틸 스탯의 투척 오차 후 안전 재검사. 기존 AutonomyChecks는 소비·효과·만료 검사를 유지하고 섬광 사용 상황을 진입 임무로 갱신했습니다. 표준 검사 실행기는 16개 묶음입니다.
- 초기 수정안은 단일 적 소리만으로 수비 연막을 쓰면서 회귀 검사에서 시야 차단 비율 45%로 실패했습니다. 다수 진입/위급 상황 조건과 팀 단위 구역 중복 제한을 추가한 뒤 같은 ContactRate 집중 검사에서 탐지 40.47%, 연막 차단 18.67%로 기준을 통과했습니다. 검사 임계값은 변경하지 않았습니다.
- 최종 검증: 공격팀의 설치 후 HoldSite에도 같은 연막 판단을 적용하고 해당 검사를 추가한 최종 코드에서 16개 검사 묶음 전체 통과(실패 0). fairness 51%, aim-at-range 76.5%, behaviour-present 통과, defender-facing 86%, engagement 40%, 연막 차단 21%. 아군 안전·전멸 후 투척 금지·진입 유틸·백업·라운드 초기화 모두 통과했습니다. Unity 내장 Mono + HeadlessStub 검증이며 이번 변경 후 Unity 화면 검증과 장기 진영 승률 측정은 하지 않았습니다.

## 33. 탄창 단위 탄약 및 재장전 (2026-09-17, Codex)

- 최종 검증: Unity 내장 Mono + HeadlessStub로 17개 검사 묶음 전체 통과(실패 0). fairness 51%, aim-at-range 76.5%, behaviour-present 통과, defender-facing 86%, engagement 40% / 연막 21%. 검사 임계값은 변경하지 않았습니다. 이번 HUD 추가는 에디터 화면에서 별도 확인하지 않았습니다.

## 39. 방어구·헬멧과 구매 AI (2026-09-17)

- AI는 근처 6m 이내의 보이는 무기를 대상으로, 자신의 총보다 등급이 높거나 자신의 예비 탄창이 0이고 현재 잔탄이 20% 이하이면 교환을 고려합니다. 바닥 총의 탄 수는 판단에 사용하지 않습니다. 무기 등급은 기본 권총 → 추가 권총 → 데저트이글 → SMG → Galil/FAMAS → 주요 소총 → AWP 순의 초기 정책입니다. 에임/무기 숙련도별 선호 순위 조정은 아직 없습니다.
- 교전·장전·실명 중이거나, 가까운 적의 공유 시야/기억·최근 소리 정보가 있거나, 체력 30 미만이면 수집하러 가지 않습니다. 설치/해제/폭탄 회수/리테이크/후퇴도 우선합니다. 같은 높이에서 바로 접근 가능한 총에 한해 조용히 접근하고, 교환 후 5초 동안 재탐색하지 않습니다. 스스로 버린 총은 자동으로 다시 줍지 않습니다. 멀리 있는 총을 찾거나 다른 층까지 탐색하는 행동은 이번 범위에 없습니다.
- 교환 시 기존 총도 당시 탄창 상태로 떨어집니다. 바닥 모델은 기존 총기 프리팹을 사용하며 떨어진 후 발밑 바닥/구조물에 내려앉습니다. 줍거나 새 라운드가 시작되면 해당 모델을 정리합니다. 굴러다니는 강체 물리나 팔로 줍는 전용 애니메이션은 없는 더미 연출입니다.
- 구매 단계의 ECO/FORCE 팀은 완료 라운드의 자체 Rating(동률이면 킬)으로 에이스를 고릅니다. 에이스가 소총급 장비를 갖고 있지 않으면 다른 선수 중 자금 여유가 가장 큰 선수가 AK/M4를 대신 구매할 수 있습니다. 팀당 라운드당 최대 한 자루이며, 첫 라운드는 성적이 없어 지원하지 않습니다. 지원자의 기존 총을 덮어쓰지 않고 새 총을 스폰 구역에서 에이스에게 짧게 던져 동일한 바닥 무기/줍기 경로로 전달합니다. 에이스가 받은 총은 일반 구매에서 다시 구매하지 않습니다.
- 이코 지원자의 잔액 + 다음 패배 보상 2,400이 본인의 다음 풀바이 필요 자금 이상이어야 합니다. FORCE에서는 지원자의 CT 방탄복 650 / T 방어구·헬멧 1,000 예산을 남깁니다. 지원자/수혜자의 이코 데저트이글 추가 구매는 취소합니다. 따라서 44절 이코 절약의 예외는 이 조건을 충족하는 팀 에이스 지원 한 자루입니다.

## 46. 비전투 프리에이밍·정보 피킹·엄폐 대기 (2026-09-17)

## 47. 초반 이동·벽 모서리 조준 보정·칼 이동 (2026-09-17)

- 자동 경기에서 라운드 시작 후 15초 동안 적 정보가 없는 탐색 피킹을 생략합니다. 초반 안전 이동에는 각도를 나누기 위한 정지/선회도 생략합니다. 실제 적 접촉/가까운 위협 정보가 생기면 15초 이전이라도 대응하며, 15초가 지나면 기존 정보 피킹을 재개합니다. 이동 속도와 맵 경로상 조기 접촉이 발생할 수 있어 적 정보를 무시하는 무적/안전 시간으로 처리하지 않았습니다.
- `VisibleAimPoint`는 예상 지점이 벽 뒤에 있으면 현재 위치에서 보이는 모서리 가장자리로 조준을 보정합니다. 비접촉 프리에이밍과 자동 피킹의 관측 방향에 연결했습니다. 짧은 피킹 목표가 여전히 벽에 가려져 있으면 시야가 실제로 열리는 노출 지점까지 이동하도록 고쳤습니다. 적의 숨겨진 실제 위치는 사용하지 않습니다.

- 달리기 최고 속도는 총 5.0 → 칼 5.75(15% 증가)입니다. 기존 가속/목적지 감속과 걷기 2.4는 유지합니다. 무빙 스탯은 이동 속도를 바꾸지 않습니다. 칼을 들고 있는 동안 총을 쏘지 않으며 총을 꺼낸 뒤에는 0.35초 사격 준비 시간이 있습니다. 총의 현재 탄창·예비 탄창은 꺼내고 넣어도 그대로입니다. 이번 칼은 이동용이며 근접 공격은 추가하지 않았습니다.

## 48. C4 운반·회수, 해체킷과 진행 게이지 (2026-09-17)

- 남은 라운드/폭탄 시간 오른쪽에 설치(주황)·해체(파랑) 진행 게이지와 완료까지 남은 초를 표시합니다. 킷으로 해체 중이면 `[KIT]`도 표시하며 5초 기준 진행률을 사용합니다. 설치/해체가 중단되면 진행 표시가 사라집니다. 다른 선수가 해체를 이어받아도 이전 사람의 진행률을 승계하지 않습니다.
- 자동 경기의 C4 담당자는 매 라운드 시드 기반으로 T 5명 중 무작위 지정합니다. 전투/전략 난수열을 소비하지 않는 별도 난수로 고릅니다. 기존 단판 검사 경로의 첫 T 지정은 유지합니다. 등에 부착하는 단순 상자+표시등 모델과 선수 카드 `C4` 표시를 연결했습니다. 설치 후에는 사이트 바닥 모델로 바뀝니다.
- `Prototype.DropC4(player)` / `PassC4(from,to)`는 생존한 운반자의 자발적 드롭/근거리 같은 진영 전달을 지원합니다. 전달 시 거리·층간·벽 차폐를 검사합니다. 기존 총기 드롭 API와 마찬가지로 감독 HUD의 직접 명령 버튼은 추가하지 않았습니다. 별도의 자동 전술 핸드오프 정책은 아직 없으며 AI 회수는 기존 RecoverBomb 오더에 연결합니다.
- 운반자 사망 시 C4는 해당 위치에 떨어집니다. 다른 살아 있는 T만 회수할 수 있고 CT는 회수하지 못합니다. 자발적으로 버린 당사자는 2초 동안 즉시 재회수하지 않습니다. 바닥/단차 높이와 차폐를 확인하며, 1.2m 미드 단차에서도 정상 회수됩니다. 바닥 C4 회수 시 설치 진행률은 0부터 시작합니다. 새 라운드에는 지면의 이전 C4를 제거하고 한 명에게 새로 지급합니다.
- 해체킷은 별도 `PlayerMatchState.defuseKit` 장비입니다. 프로토타입 가격 400, 해체 시간은 기존 기본 10초의 절반인 5초입니다. CT 팀 FULL 계획에서 이미 보유한 선수 포함 3명을 목표로 여유 자금이 많은 선수에게 구매를 배정합니다. 총/방어구 확보 후 킷을 사고 남는 돈으로 유틸을 삽니다. 구매 가능한 예산이 부족하면 3명보다 적게 구매하며 PISTOL/FORCE/ECO에서는 새 킷을 사지 않습니다.
- 킷은 자발적 드롭 API가 없습니다. 사망 시 장비에서 제거하고 파란 더미 상자로 바닥에 놓습니다. 킷 없는 CT가 안전한 상황에서 1.5m 이내에 접근하면 회수할 수 있습니다. T는 회수하지 못합니다. 같은 CT 진영 내 생존 보유자는 다음 라운드에도 유지하고, T로 전환되거나 새 매치를 시작하면 킷을 제거합니다. 새 라운드의 바닥 킷은 정리합니다.
- 해체 가능 범위 내에서는 킷 보유자를 우선 선정합니다. 설치/해체의 기존 소리 정보는 유지합니다. HUD의 KIT/C4 표시는 장비 상태이며 내부 AI 의도 표시는 아닙니다. 킷은 바닥 더미와 HUD로 표현하며 착용 애니메이션, C4 투척 강체 물리, 설치 손동작은 아직 없습니다.
- `BombEquipmentChecks`는 T 무작위 지급, 전달/드롭/회수 및 CT 제한, 단차 C4 회수, 킷 사망 드롭/CT 회수, 풀바이 3명·가격·중복/잔액 보호, 실제 5초/10초 해체, 해체자 교체 시 진행 초기화를 검사합니다. `BombVisualChecks.Run`으로 Unity 더미 모델과 장비 검사, 자연 AI 경기를 검증할 수 있으며 `BOMB_QA_OUTPUT`이 캡처 폴더입니다. HUD 화면 검증은 진행률을 고정한 임시 fixture입니다.
