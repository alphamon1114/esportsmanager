# Esports Manager — Unity FPS 감독 시뮬레이션

CS 1.6·CS2 같은 클래식 5대5 FPS 팀을 운영하고 관전하는 게임입니다. **2D 전술 지도와 선택 선수의 1인칭 화면을 동시에 보여주는 것**이 핵심입니다.

- 저장소: https://github.com/alphamon1114/esportsmanager
- Unity: **6000.6.0f1** (`ProjectSettings/ProjectVersion.txt` 기준)
- 인수인계 갱신일: **2026-09-15** (4차 세션: 라운드 진행과 목표 기반 행동 추가)
- 현재 단계: **한 라운드가 끝까지 진행됩니다.** 배치 → 라인 집결 → T의 사이트 진입과 폭탄 설치 → CT의 방어·후퇴·로테이트·리테이크·해체 → 승패 판정.
- 아직 한 맵을 진행할 수 없습니다. 라운드 간 점수, 9선승·듀스, 공수 교대, 구매·경제, 타임아웃은 미구현입니다.
- 60판 측정 기준 수비 60% / 공격 40%, 폭탄 설치율 53%, 평균 라운드 길이 37.8초. **밸런싱된 수치가 아니라 현재 상태의 측정값입니다.**

## 1. 다른 컴퓨터 / 다른 AI에서 시작하기

1. 저장소를 clone하고 Unity Hub에 저장소 루트 폴더를 추가합니다. 이 폴더 자체가 Unity 프로젝트이며 별도의 `UnityProject` 하위 폴더는 없습니다.
2. 지정 Unity 버전으로 열고 패키지 가져오기와 컴파일이 끝날 때까지 기다립니다.
3. `Assets/Scenes/Prototype.unity`를 열고 **Play**를 누릅니다.
4. 팀 스피릿 선수를 선택하고 **Initial zone** 버튼으로 담당 구역을 지정합니다.
5. **Start round**를 누르면 라운드가 시작됩니다. T는 지정 라인에 모였다가 목표 사이트로 진입하고, CT는 방어합니다.
6. 지도 또는 오른쪽 목록에서 선수를 선택하면 1인칭 시점이 전환됩니다.
7. **Pause / Resume**은 관전 일시정지, **Reset / next seed**는 시드를 1 올리고 준비 상태로 되돌립니다.
8. **Swap starting sides**는 준비 단계에서만 가능한 테스트 기능입니다. 공수를 바꾸어도 조작 팀은 스피릿입니다.
9. **Fog of war** 버튼으로 관전 정보 제한을 켜고 끕니다. ON이면 지도에 스피릿이 탐지한 팔콘즈만 표시되고, OFF면 전원이 표시됩니다. 이 버튼은 개발 확인용입니다.

현재 개발 컴퓨터의 경로는 `C:\unity\esportsmanager`입니다. 다른 컴퓨터에서는 경로를 자유롭게 정해도 됩니다. 예전 `Documents/ChatGPT/FPS 시뮬레이션` 경로나 외부 원본 JSON이 실행에 필요하지 않습니다.

### 작업 방식

- **그래픽은 최대한 더미로 유지합니다.** 벽·엄폐물은 큐브, 선수는 캡슐, UI는 기본 IMGUI를 사용합니다. 사용자는 토큰과 작업량을 줄이고 기능 구현에 집중하기를 원합니다.
- 외부 모델·텍스처·애니메이션이나 UI 장식 작업은 현재 범위가 아닙니다.
- 아래의 **구현 완료 / 확정 기획 / 수치 초안 / 미결정 항목**을 구분합니다. README의 기획이 전부 코드에 구현되어 있다고 가정하지 않습니다.
- 변경할 때 이 문서의 현재 상태와 변경 이력에 **무엇을 바꿨는지, 왜 바꿨는지, 어떻게 검증했는지, 남은 한계**를 갱신합니다.
- Unity에서 열어 둔 프로젝트를 강제 종료하지 않습니다. 배치 검사가 필요하면 에디터를 닫거나 임시 복사본에서 실행합니다.

### 적 탐지 규칙

- 관찰자마다 정면 기준 좌우 50도, 최대 55단위까지 봅니다. 반경 5단위 안은 시야각을 무시합니다.
- 벽과 엄폐물 상자는 시야를 **완전히** 차단합니다. 높이 개념과 부분 엄폐는 없습니다.
- 보이기 시작해도 즉시 인지하지 않습니다. `0.15초 + 거리 × 0.004초`만큼 계속 보여야 접촉으로 등록됩니다.
- 접촉은 **팀 전체가 공유**합니다. 라디오 시스템이 생기기 전까지 음성 소통을 대신하는 단순화입니다.
- 시야가 끊기면 즉시 `visible=false`가 되고, 마지막 목격 위치를 6초간 기억한 뒤 잊습니다.
- **청각:** 움직이는 적이 18단위 안에 있으면 벽 너머나 등 뒤에서도 접촉으로 잡힙니다. 들은 접촉은 `known`이지만 `visible`이 아니므로 **판단에는 쓰이고 사격에는 쓰이지 않습니다.**
- 청각이 없으면 수비 판단이 성립하지 않습니다. 적을 보는 순간과 사살당하는 순간이 1초 안에 겹치기 때문에, 시야만으로는 "버틸 수 없다"고 판단할 시간이 물리적으로 존재하지 않습니다. `hearingRange`를 0으로 두면 꺼집니다.
- 난수를 쓰지 않습니다. 같은 입력이면 같은 접촉 결과가 나옵니다.

수치는 모두 **테스트 시작값**이며 밸런싱되지 않았습니다. `Assets/Scripts/Vision.cs`의 `VisionSettings`에 모여 있습니다.

### 교전 규칙

- 적을 보면 그 자리에 멈춰 싸웁니다. 이동 사격 부정확도가 없으므로 정지가 정직한 단순화입니다. 후퇴 명령을 받은 선수만 예외적으로 계속 움직입니다.
- 사격 대상은 **본인이 직접 보고 있는** 적 중 가장 가까운 한 명입니다. 팀이 공유한 접촉만으로는 쏘지 않습니다.
- 접촉을 잡으면 `0.25초 ± 40%`의 반응 시간이 지나야 첫 발이 나갑니다. 반응 시간은 개인차가 있습니다.
- 명중은 확률이 아니라 **기하**로 정합니다. 조준선에 오차각을 더하고, 그 각도로 거리를 곱한 횡오차가 대상 반지름 0.6단위 안이면 명중입니다.
- 오차각의 기준 폭은 3도이고 에임 스탯으로 배율이 붙습니다. 에임 0에서 1.6배, 100에서 0.5배입니다.
- 대미지는 몸통 고정 36. 방어구·부위 판정이 없으므로 3발이면 사망합니다.
- 조준선에 아군이 5도 안으로 들어와 있고 더 가까우면 사격을 보류합니다.
- 난수는 라운드 시드로 초기화한 splitmix32만 씁니다. `UnityEngine.Random`은 시뮬레이션 코드에서 쓰지 않습니다.
- **정지한 선수만 조준을 바꿉니다.** 이동 중인 선수는 진행 방향을 보므로, 앞쪽의 적은 쏠 수 있고 뒤쪽의 적은 쏠 수 없습니다. 달리면서 돌아 쏘기는 없습니다.

이 수치로 측정한 결과입니다. 밸런싱 목표가 아니라 모델이 의도대로 동작하는지 확인한 값입니다.

| 조건 | 거리 | 앞선 선수 승률 | 명중률 |
|---|---:|---:|---:|
| 에임 동일 (85 : 85) | 16 | 50.0% | 100% |
| 에임 동일 (85 : 85) | 54.9 | 50.5% | 64.5% |
| 에임 98 : 72 | 16 | 50.2% | 99.9% |
| 에임 98 : 72 | 25 | 62.2% | 95.1% |
| 에임 98 : 72 | 54.9 | 74.0% | 66.1% |

근거리는 명중이 사실상 확정이라 **반응 시간이 승부를 가르고**, 거리가 멀어질수록 에임이 결정적이 됩니다. CS에서 기대하는 모양이지만 검증된 밸런스는 아닙니다.

### 라운드 규칙

| 항목 | 값 | 비고 |
|---|---:|---|
| 라운드 시간 | 115초 | 넘기면 수비 승 |
| 실행 대기 | 최대 25초 | T 전원이 지정 라인에 모이면 그 전에 실행 |
| 설치 | 3.2초 | 중단되면 처음부터 |
| 해체 | 10초 | 해체 키트 없음 |
| 기폭 | 40초 | |

- 종료 사유는 다섯 가지입니다. 폭발, 해체, 공격 전멸, 수비 전멸, 시간 초과.
- **설치된 폭탄은 라운드를 살려 둡니다.** 공격이 전멸해도 끝나지 않고, 수비가 전멸하면 해체할 사람이 없으므로 즉시 공격 승입니다.
- 폭탄 운반자는 라운드 시작 시 공격 1명에게 배정됩니다. 죽으면 그 자리에 떨어지고, 가장 가까운 공격이 회수하러 갑니다.

### 행동 규칙

모든 판단은 `VisionSystem`이 실제로 관측한 정보만 씁니다. 상대의 진짜 좌표를 읽는 곳은 한 군데도 없습니다. `ROUND_CASE_OK observed-information-only` 검사가 이를 고정합니다.

**공격(T)**

- 지정 배치 구역을 **진입 라인**으로 씁니다. 전원이 라인에 모이면 함께 실행하고, 25초가 지나면 강제로 실행합니다.
- 목표 사이트는 라운드 시드로 뽑습니다. 6단계의 사전 전술 설정이 들어올 자리의 임시 구현입니다.
- 운반자는 설치 지점으로, 나머지는 사이트 주변 5개 지점으로 퍼집니다. 설치 전 진입로를 막는 자리와 설치 후 지키는 자리가 같습니다.
- 설치는 운반자가 설치 지점에 있고, **교전 중이 아니며**, 팀이 사이트 20단위 안에서 수비를 보고 있지 않을 때만 진행됩니다.

**수비(CT)**

- 배치 구역이 사이트 안이면 그 사이트를 지킵니다. 사이트가 아니면(중앙 등) 대기하다가, 팀이 적을 가장 많이 관측한 사이트로 **로테이트**합니다.
- **후퇴 판단:** `관측한 적 수 > 사이트 근처 생존 아군 수 + 여유`. 여유는 침착함 90 이상이면 1, 아니면 0입니다. 즉 침착한 선수는 한 명 열세까지 버팁니다.
- 후퇴 중에는 진행 방향을 보므로 뒤를 쏘지 못합니다. 재집결 지점에 닿으면 다시 서서 그 방향을 지킵니다.
- 재집결 지점은 하드코딩이 아니라 **수비 스폰에서 사이트까지의 경로를 16단위 되짚어** 구합니다. 지형을 바꿔도 항상 도달 가능한 자리가 나옵니다.
- 폭탄이 설치되면 전원이 폭탄으로 향하고, 폭탄에 닿은 선수가 교전 중이 아니면 해체를 시작합니다.

**감시 방향** — 서 있는 선수는 팀이 가진 가장 가까운 접촉을 봅니다. 접촉이 없으면 상대가 들어올 방향을 봅니다. 수비는 재집결 지점 반대편을, 설치 후 공격은 재집결 지점 쪽을 봅니다.

60판 측정 결과입니다. 밸런싱 목표가 아니라 현재 상태의 기록입니다. CT 배치는 B 2명 / 중앙 2명 / A 1명입니다.

| 항목 | 값 |
|---|---:|
| 수비 승 | 60% |
| 공격 승 | 40% |
| 폭탄 설치 | 53% |
| 평균 라운드 길이 | 37.8초 |
| 후퇴가 나온 라운드 | 20 / 60 |
| 로테이트가 나온 라운드 | 60 / 60 |
| 리테이크가 나온 라운드 | 32 / 60 |

폭발로 끝난 라운드는 0판입니다. 수비가 전멸하거나 해체에 성공하는 두 결말로 갈립니다.

### 현재 한계

- **라운드 간 상태가 없습니다.** 점수, 9선승, 듀스, 공수 교대, 타임아웃이 없어 한 라운드만 반복해서 돌립니다.
- 목표 사이트는 시드 추첨입니다. 상대 분석이나 사전 전술이 아닙니다.
- 팔콘즈의 초기 배치는 고정 기본값입니다. 라운드가 시작되면 양 팀이 같은 판단 규칙을 쓰므로 실력 차이는 스탯에서만 나옵니다.
- 교전 중에는 **엄폐도 피킹도 트레이드도 없습니다.** 후퇴만 있고, 마주 본 채 끝까지 쏩니다.
- 후퇴는 사이트 단위 인원 비교 하나로만 결정됩니다. 체력, 남은 시간, 폭탄 위치, 유틸 보유는 판단에 들어가지 않습니다.
- 재집결한 수비는 리테이크 타이밍을 스스로 잡지 않습니다. 폭탄이 설치되어야 다시 들어갑니다. 설치되지 않으면 그 자리에 계속 서 있습니다.
- 총기는 1종 고정입니다. 구매, 로드아웃, 재장전, 탄약, 노획, 유틸, 방어구, 부위 판정이 없습니다.
- 탐지에 스탯을 반영하지 않습니다. 침착함은 후퇴 판단에만 쓰이고, 무빙은 아직 아무 데도 쓰이지 않습니다.
- 시야 판정은 2D 평면 기준입니다. 눈높이·웅크리기·엄폐물 너머 보기는 없습니다. 청각은 거리만 보고 벽·바닥을 고려하지 않으며, 들린 적의 위치를 **정확히** 알려줍니다. 실제 게임보다 후한 단순화입니다.
- **이동 테스트 모드에서는 여전히 접촉이 한 번도 없습니다.** 배치 구역 9쌍이 서로 보이지 않기 때문입니다. 라운드 모드에서는 양 팀이 사이트로 수렴하므로 문제가 되지 않습니다.
- 선수끼리 이동 중 충돌을 피하는 기능은 없습니다. 경로가 겹치면 서로 통과할 수 있습니다.
- 이동 속도는 테스트용 고정값 5입니다. 에임을 제외한 스탯과 총기 숙련도는 데이터 및 표시만 존재하며 행동·교전 보정은 적용하지 않습니다.
- 시뮬레이션 간격은 Unity 프레임 시간이고 최대 0.1초로 제한됩니다. 프레임 레이트가 다르면 교전 결과가 달라질 수 있습니다. 자동 검사는 0.05초 고정 간격으로 돌립니다.
- 맵 좌표와 보행 공간은 초기 더미입니다. CT 우세 밸런스와 이동 시간은 검증되지 않았습니다.
- 적 선수의 관전 선택은 여전히 가능합니다. **상대 배치 조작 금지**와 **관전 정보 제한**은 별개입니다. 정보 제한은 지도 마커에만 적용되고, 1인칭 화면은 실제 카메라이므로 별도 은폐가 필요 없습니다.
- UI는 개발용 영어이고 1280×800 기준 비례 확대입니다. 작은 Game 뷰에서는 이름표가 겹칠 수 있고, 접촉 목록이 5명이면 한 줄을 넘칠 수 있습니다.

### 좌표와 구현 주의점

- 지도 좌표는 대략 0~100 범위이며, `(x, y)`는 월드 `(x, height, 100-y)`로 변환됩니다.
- `Box`로 생성하는 `Wall`과 `Cover`는 이동 장애물 사각형에도 등록됩니다. 지형을 바꿀 때 렌더링과 경로 탐색의 장애물 정의를 함께 유지합니다.
- `DeploymentNavigation`은 장애물을 **두 벌** 씁니다. `Clear`는 캡슐 반지름만큼 부풀린 사각형으로 이동 가능 여부를, `SightClear`는 부풀리지 않은 원본 사각형으로 시야를 판정합니다. 시야에 여유 폭을 적용하면 벽을 따라 스치는 시선이 잘못 끊깁니다. 지형 코드를 고칠 때 이 구분을 유지합니다.
- 탐지는 `SimulateMovement` 안에서 이동 뒤에 갱신되므로, 준비 단계에 서 있을 때나 이동이 끝난 뒤에도 계속 돕니다. Pause 중에는 멈춥니다.
- 아군 여부 판단과 마찬가지로 시야 팀 구분도 `teamId` 기준입니다. 공수 교대와 무관하게 팀 지식이 유지됩니다.
- **한 틱 안의 사격 순서에 주의합니다.** `CombatSystem.Tick`은 두 패스로 나뉩니다. 1패스에서 각자가 틱 안 언제 사격 가능해지는지를 소수점 시간으로 구하고, 2패스에서 그 시간 순으로 처리합니다. 반응 시간과 쿨다운을 0으로 잘라내면 모두가 "틱 시작 시점"에 사격하게 되어, 승부가 배열 순서로 결정됩니다. 개발 중 이 문제로 앞선 선수가 74~80% 이겼습니다.
- `Fire`는 쿨다운을 건드리지 않습니다. 쿨다운은 호출부가 소수점 시간을 담아 설정합니다. 여기서 고정값으로 덮어쓰면 위와 같은 증상이 되돌아옵니다.
- 난수는 반드시 `DeterministicRandom`을 씁니다. 작은 정수 시드에서 초기 출력이 상관되는 생성기(xorshift 등)로 바꾸면 먼저 추첨한 선수가 유리해집니다. `COMBAT_CASE_OK fairness`가 이를 잡습니다.
- 선택 선수는 레이어 8로 두고 1인칭 카메라에서만 제외합니다. 향후 레이어를 추가할 때 이 용도를 보존하거나 명시적으로 대체합니다.
- 아군 여부는 CT/T나 배열 순서가 아니라 **teamId `spirit`**로 판단합니다. 상대 명령은 UI에서 숨기는 동시에 `AssignZone`에서도 거부합니다.
- `Prototype` MonoBehaviour와 데이터 클래스는 별도 파일을 유지합니다. 씬을 저장했다가 다시 열어도 컴포넌트가 유지되는지 확인합니다.
- **모드가 둘입니다.** `BeginDeployment`는 예전의 이동 테스트(각자 구역으로 한 번 걸어가고 정지)이고, `BeginRound`가 실제 라운드입니다. 배치·탐지·교전 검사는 전부 이동 테스트 모드를 대상으로 쓰였으므로, 그 동작을 바꾸면 25개 검사가 함께 깨집니다. 라운드 쪽을 고칠 때 이동 테스트 경로를 건드리지 않습니다.
- 라운드 한 틱의 순서는 **지난 틱에 정해진 목표대로 이동 → 보고 듣기 → 사격 → 관측한 것으로 다음 목표 결정**입니다. 목표가 한 틱 늦게 반영되는 것은 의도입니다.
- `Route`는 격자 전체 탐색이라 비쌉니다. 목표가 실제로 바뀌었을 때만, 선수당 최대 0.5초에 한 번만 다시 계산합니다. 매 틱 재탐색하도록 바꾸지 않습니다.
- 감시 방향을 "사이트 중심 쪽"으로 두지 않습니다. 수비 배치 좌표가 사이트와 거의 같아서 방향 벡터가 퇴화하고, 수비수가 엉뚱한 곳을 봅니다. 개발 중 이 문제로 수비가 12판 전패했습니다.
- 후퇴에는 `PlayerObjective.disengage`가 필요합니다. 이것이 없으면 적을 본 수비수는 교전 상태로 고정되어 **자리를 뜰 수 없습니다.** `ROUND_CASE_OK behaviour-present`가 후퇴·로테이트·리테이크가 실제로 일어나는지 확인합니다.

## 4. 확정된 게임 방향 — 대부분 구현 예정

### 경기와 감독 개입

- 클래식 5대5 폭탄 설치형 FPS. 캐릭터 고유 스킬은 없습니다.
- 기본 9라운드 선승. **8:8이면 듀스**, 2라운드 차이가 나야 맵 승리입니다.
- 정규전 8라운드 종료 후 공수 교대. 연장에서는 매 라운드 교대합니다.
- 타임아웃은 **팀당 맵 전체 2회**, 연장 추가 지급은 없습니다.
- **전략·전술 변경은 타임아웃에만 가능**합니다.
- 매 라운드 시작 전에는 총기·유틸 구매와 주요 지점 인원 배치를 지정합니다.
- 라운드 중에는 선수가 준비된 전술과 자신이 얻은 정보에 따라 판단합니다. 감독의 실시간 이동 명령 기능을 넣지 않습니다.
- 준비된 공수별 전술을 맵 시작 전 설정하는 방식은 앞서 제안되었으며 구체적인 UI·전술 항목은 후속 설계 대상입니다.

### 관전 표시

- 메인은 2D 전술 지도, 보조는 선택 선수의 1인칭 화면입니다.
- 은폐 대기·우회·진입·사격 보류 같은 **내부 행동/판단 텍스트를 표시하지 않습니다.** 움직임과 교전으로 판단을 읽는 것이 의도입니다.
- 향후 행동 관련 표시는 “섬광 투척”, “연막 투척”처럼 **실제로 발생한 라디오 메시지**만 사용합니다. 라디오 시스템은 아직 없습니다.
- 체력·장비 같은 기본 상태 표시는 가능합니다.

### 포지션

- 총기 포지션: **오퍼 / 라이플러**.
- 라이플러 세부 역할: **엔트리 / 앵커·럴커**.
- 앵커·럴커는 같은 분류이며 CT에서는 사이트 유지, T에서는 별동·이동 차단 등을 맡습니다.
- 팀 포지션 인원 구성은 강제하지 않습니다. IGL은 포지션과 별도로 1명 지정합니다.
- 포지션은 사용 가능 총기를 제한하지 않습니다.

### 기본 스탯 (1~100)

| 스탯 | 의도한 영향 |
|---|---|
| 에임 | 조준·명중·반동 제어 등 기본 사격 실력 |
| 유틸 | 투척 위치와 타이밍, 적중 및 차단 효과 |
| 무빙 | 피킹, 좌우 움직임, 정지 사격 전환. 상대 원탭을 피하는 행동 |
| 카리스마 | IGL 지정 시 팀원 추가 스탯 |
| 침착함 | 급발진 감소, 클러치·트레이드 대응 향상, 은폐 상태에서 정보와 멀티킬 기회 판단 |

침착함이 높으면 첫 적을 즉시 쏘지 않고 후속 적을 기다릴 수 있지만, 무조건 오래 기다리는 것은 아닙니다. 발각 위험·아군 지원·기회 소실을 고려해야 합니다. 상대의 숨겨진 인식 상태를 그대로 읽는 대신 관측한 단서로 판단하는 방향입니다.

IGL이 다른 4명의 기본 스탯에 최대 +5를 주고 카리스마에는 중복 보너스를 주지 않는 방식은 **수치 초안**이며 아직 코드에 적용되지 않았습니다. 사망 시 보너스 유지 여부와 계산식도 구현 전에 명시합니다.

### 경제 — 채택한 초기 방향, 구현·밸런싱 전

짧은 전반 8라운드에 맞춰 **한 라운드 절약 후 구매력을 회복**하도록 설계합니다. 아래 수치는 테스트 시작값입니다.

| 항목 | 개인 크레딧 |
|---|---:|
| 전·후반 시작 | 800 |
| 승리 | 3,200 |
| 첫 패배 | 2,000 |
| 2연패 | 2,500 |
| 3연패 이상 | 3,000 |
| 킬 | 처치자 +200, 총기별 차이 없음 |
| 폭탄 설치 | T 전원 +300, 승패 보상과 중복 |
| 보유 상한 | 9,000 |

- 정규 하프타임에 자금·장비 초기화하는 방향을 채택했습니다.
- 승리하면 패배 보상 단계를 한 단계 낮추는 안입니다. 예: 3연패 → 승리 → 패배 시 2,500. 연속 승리 등 전체 전이표는 경제 구현 때 정의해야 합니다.
- 해체 승리는 승리 보상에 포함하고 별도 해체 보너스는 두지 않는 안입니다.
- **연장에서는 잔액 유지, 일반 승패 보상만 적용, 별도 연장 보너스 없음**이 확정입니다.
- 연장 공수 교대 시 생존 장비를 어떻게 처리할지는 미결정입니다. 크레딧 유지와 장비 유지는 같은 결정이 아닙니다.
- 라이플 풀바이 약 4,500~5,000, AWP 풀바이 약 6,000~6,500이 목표 범위이며 개별 가격은 아직 없습니다.

## 6. 검증 방법

### 자동 검사

프로젝트를 에디터에서 닫은 상태 또는 임시 복사본에서 PowerShell로 실행합니다. 경로는 각 컴퓨터에 맞게 바꿉니다.

```powershell
$unityExe = 'C:\Program Files\Unity\Hub\Editor\6000.6.0f1\Editor\Unity.exe'
$projectPath = 'C:\unity\esportsmanager'
$logPath = Join-Path $env:TEMP 'esportsmanager-deployment-check.log'
& $unityExe -batchmode -nographics -projectPath $projectPath -executeMethod DeploymentChecks.Run -quit -logFile $logPath
```

탐지·교전·라운드 검사도 같은 방식으로 실행합니다.

```powershell
& $unityExe -batchmode -nographics -projectPath $projectPath -executeMethod VisionChecks.Run -quit -logFile $logPath
& $unityExe -batchmode -nographics -projectPath $projectPath -executeMethod CombatChecks.Run -quit -logFile $logPath
& $unityExe -batchmode -nographics -projectPath $projectPath -executeMethod RoundChecks.Run -quit -logFile $logPath
```

실행 프로세스가 끝난 후 로그에서 **`DEPLOYMENT_ALL_OK`**, **`VISION_ALL_OK`**, **`COMBAT_ALL_OK`**, **`ROUND_ALL_OK`**와 정상 종료를 확인합니다. Windows에서 실행 명령만 반환되었다고 검사가 끝났다고 판단하지 않습니다.

현재 검사는 양쪽 시작 진영 × 아군 분산/각 구역 집중 배치 = **8개 구성**을 대상으로 다음을 확인합니다.

- 스피릿 배치 명령 허용 / 팔콘즈 배치 명령 거부.
- 시작 후 배치 명령 잠금.
- 스폰 및 이동 중 벽·엄폐물과의 겹침 없음.
- 제한된 시뮬레이션 시간 안에 이동 완료.
- 이동 중 선수 시점 선택 가능.

최종 아군 제한 변경 후 위 8개 검사는 통과했습니다. 상대는 고정 기본 배치로 검사하며, 현재 검사가 상대의 모든 집중 배치 조합까지 검증하는 것은 아닙니다.

`VisionChecks.Run`은 다음 9개 항목을 확인합니다. 각각 `VISION_CASE_OK <이름>`을 남깁니다.

| 항목 | 확인 내용 |
|---|---|
| frontal | 개활지에서 정면 근거리 대상이 보임 |
| field-of-view | 같은 대상이 등 뒤에 있으면 보이지 않음 |
| peripheral | 반경 5단위 안에서는 시야각을 무시함 |
| range | 최대 사거리를 넘으면 시선이 통해도 보이지 않음 |
| obstruction | 지형을 통과하는 시선이 차단됨. 검사 지점은 실행 시 맵에서 직접 찾음 |
| recognition | 인지 시간 전에는 접촉으로 등록되지 않고, 노출이 쌓이면 등록됨 |
| memory | 시야가 끊기면 `visible=false`, 마지막 목격 위치 유지, 6초 후 소멸 |
| information-separation | 스폰 직후 양 팀 모두 상대 위치를 하나도 모름 |
| determinism | 같은 입력 두 번이 같은 접촉 기록을 만듦. 접촉이 실제로 발생하는 시나리오로 확인 |

마지막에 `VISION_ZONE_SIGHT` 9줄이 **진단 정보**로 출력됩니다. 단언이 아니므로 검사를 실패시키지 않습니다. 현재 값은 `VISION_ZONE_SIGHT_PAIRS 0 of 9`입니다.

`CombatChecks.Run`은 다음 8개 항목을 확인합니다.

| 항목 | 확인 내용 |
|---|---|
| resolution | 개활지 대치가 제한 시간 안에 한쪽 사망으로 끝남 |
| determinism | 같은 시드가 체력 변화까지 같은 라운드를 재생 |
| seed-sensitivity | 시드를 바꾸면 결과가 달라짐. 난수가 실제로 소비되는지 확인 |
| obstruction | 벽 너머로는 사격도 피해도 없음 |
| range | 사거리 밖에서는 시선이 통해도 사격 없음 |
| no-contact-no-damage | 접촉이 없는 정상 배치 라운드에서 사격 0, 피해 0 |
| fairness | 동일 실력 200판의 선행 선수 승률이 42~58% |
| aim-at-range | 장거리에서 에임 98이 에임 72를 58% 넘게 이김 |

`fairness`와 `aim-at-range`는 **통계 검사**입니다. 시드 집합이 고정이라 결과는 결정적이며 무작위로 실패하지 않습니다. 두 항목은 개발 중 실제로 발생했던 결함 — 배열 순서가 승부를 결정하던 문제와, 오차각이 너무 작아 에임이 무의미하던 문제 — 을 고정하기 위한 것입니다. 수치 조정으로 이 검사가 깨지면 조정이 잘못된 것인지 먼저 의심합니다.

참고로 한 판을 눈으로만 보면 두 결함 모두 정상으로 보입니다. 교전 관련 수치를 바꿀 때는 단판 확인이 아니라 이 통계 검사를 신뢰합니다.

`RoundChecks.Run`은 다음 8개 항목을 확인합니다.

| 항목 | 확인 내용 |
|---|---|
| termination | 12판 전부 제한 시간 안에 정해진 사유로 종료. 매 틱 폭탄 불변식 확인 |
| determinism | 같은 시드가 같은 라운드를 재생 |
| outcome-variety | 시드에 따라 종료 사유가 갈림. 라운드가 정해진 각본이 아닌지 확인 |
| behaviour-present | 설치·후퇴·로테이트·리테이크가 **실제로 발생**함 |
| observed-information-only | 시야와 청각을 끈 수비는 사이트 위에 적이 서 있어도 반응하지 않음 |
| bomb-explodes | 아무도 오지 않는 폭탄은 40초 후 폭발 |
| bomb-defused | 방해 없는 폭탄은 10초 만에 해체 |

`behaviour-present`는 특히 중요합니다. 후퇴·로테이트·리테이크는 개발 중 **각각 한 번씩 조용히 사라진 적이 있고**, 그래도 라운드는 정상적으로 끝나고 겉보기에 그럴듯했습니다. 행동 규칙을 고칠 때 이 검사를 먼저 봅니다.

`observed-information-only`는 4절의 정보 분리 원칙을 코드로 고정한 것입니다. 판단 로직에서 상대의 실제 좌표를 읽으면 이 검사가 깨집니다.

Unity 없이 로직만 빠르게 회귀 확인하고 싶다면, `UnityEngine` 최소 대역 클래스를 만들어 `Assets/Scripts`와 `Assets/Editor`를 `mcs`로 컴파일해 `DeploymentChecks.Run`과 `VisionChecks.Run`을 직접 호출하는 방법이 있습니다. 이 방식은 렌더링·에디터 연동을 검증하지 않으므로 Unity 배치 검사를 대체하지 않습니다.

`PrototypeSetup.CreateScene`은 **씬을 재생성하는 도구**입니다. 기존 씬을 덮어쓸 수 있으므로 커스텀 편집이 있는 작업 씬에는 무심코 실행하지 않습니다. 실행 시 `FPS_PROTOTYPE_SMOKE_OK`, `FPS_SCENE_RELOAD_OK`가 성공 표시입니다.

### 수동 확인

- Play 시작 시 두 팀이 각자 스폰에 모이는지 확인합니다.
- 스피릿을 선택했을 때만 Initial zone이 나오는지 확인합니다.
- 팔콘즈 선택 시 배치 버튼·예정 배치 인원 수가 노출되지 않는지 확인합니다.
- 공수를 바꿔도 스피릿만 조작 가능한지 확인합니다.
- 이동 중 2D와 1인칭 위치가 일치하는지, Pause / Resume과 Reset이 작동하는지 확인합니다.
- 상단 표시가 `SETUP` → `LIVE` → (설치 시) `BOMB DOWN at A/B` → `ROUND OVER`로 진행되는지 확인합니다.
- **Fog of war ON에서 지도에 팔콘즈 마커가 보이지 않다가, 스피릿이 탐지하면 나타나는지** 확인합니다. 시야가 끊긴 뒤에는 마지막 목격 위치에 `?`가 붙습니다.
- 내부 행동·공격 목표는 기본 숨김입니다. 개발 확인 시 `Debug: ON`을 켜서 오른쪽 `BOMB ... TARGET ... <선수>: <행동>` 줄을 봅니다. 선수를 바꿔 가며 행동이 `DefendSite` → `FallBack` → `Regroup` → `Retake` → `Defuse`로 바뀌는지 확인합니다.
- 상단 `ALIVE`가 줄어들고 지도에서 사망자가 `x 이름`으로 회색 처리되는지 확인합니다.
- 상단 `SEED`를 확인합니다. `Reset / next seed`를 누르면 1 증가하며, 같은 시드로 돌리면 같은 라운드가 그대로 재생됩니다.
- 이동 테스트 모드는 UI에서 빠졌습니다. `DeploymentChecks`와 `VisionChecks`가 그 모드를 사용하며, 코드에서는 `BeginDeployment`로 접근합니다.
- 그래픽 출력은 `-nographics` 검사로 검증되지 않습니다.

## 7. 다음 작업 계획

1~4단계는 **부분적으로** 구현했습니다. 한 라운드는 끝까지 진행되지만, 라운드를 이어 붙이는 층과 교전의 세부가 남아 있습니다. 아래에서 구현된 것과 남은 것을 구분합니다.

- 1단계 적 탐지 — **구현.** 청각 포함.
- 2단계 최소 교전 — **구현.** 이동 중 교전까지 확장됨.
- 3단계 전투와 이동 연결 — **절반.** 후퇴와 로테이트는 되지만 엄폐·피킹·트레이드는 없음.
- 4단계 라운드 상태 — **절반.** 한 라운드는 완결되지만 맵 단위 진행이 없음.
- 0단계 맵 시야 — **우선순위 낮아짐.** 아래 참조.

### 0단계 — 맵 시야 확보 (우선순위 내려감)

**목표 기반 행동이 들어오면서 이 문제의 긴급성이 사라졌습니다.** 양 팀이 같은 사이트로 수렴하므로 접촉이 이동 중에 자연히 발생합니다. 남은 영향은 이동 테스트 모드에서 접촉이 없다는 것뿐이고, 그 모드는 이제 검사 전용입니다. 아래 내용은 나중에 맵을 손볼 때를 위해 남겨 둡니다.

- 원인: 맵 생성이 경로 중심선에서 4.5단위 안쪽만 개활지로 만들기 때문에, 각 구역이 서로 다른 복도의 모퉁이 너머에 놓입니다. 실제 인페르노의 미드처럼 **양 팀이 마주 보는 직선 구간이 없습니다.** 맵에 직선 구간 자체는 있습니다. 가장 긴 개활 시선은 `(17.5,81.5) → (71.5,91.5)`의 54.9단위이며 T 스폰 쪽 복도입니다.
- **후보 A — 구역 좌표만 이동.** 지형을 건드리지 않습니다. 임시 적용해 측정했습니다.

  | 구역 | 현재 | 후보 A | 이동량 |
  |---|---|---|---:|
  | CT B site | (18,22) | (18,21) | 1.0 |
  | CT Mid / Arch | (65,38) | (68,44) | 6.7 |
  | CT A site | (83,33) | (84,32) | 1.4 |
  | T Banana | (27,55) | (30,55) | 3.0 |
  | T Mid | (45,61) | (41,58) | 5.0 |
  | T Apartments | (89,63) | (91,63) | 2.0 |

  결과: 시야 쌍 0 → **3**. B↔바나나 36.1, 미드↔미드 30.4, A↔아파트 31.8단위로 **라인별 한 쌍씩** 열리고 교차 라인은 막힌 채 유지됩니다. `DEPLOYMENT_ALL_OK`와 `VISION_ALL_OK` 모두 재통과하며, 기본 배치에서 14.6초에 첫 접촉이 발생합니다.

  한계: 접촉이 **양 팀 1명씩, 도착 직후에만** 생깁니다. 구역이 한 점이라 그 시선 위에 서는 선수만 보입니다. 이동 중 접촉은 여전히 없습니다.
- **후보 B — 미드 직선 구간 신설.** 지형이 바뀌므로 8개 배치 검사와 이동 시간을 다시 봐야 합니다. 아직 측정하지 않았습니다.
- **후보 C — 구역을 점이 아니라 짧은 구간으로 정의.** 선수별 도착 지점을 시선 방향으로 정렬해 한 라인에 2~3명씩 맞붙게 합니다. 후보 A의 "1명씩만 보인다" 한계를 직접 겨냥합니다. 아직 측정하지 않았습니다.
- **미결정:** 어느 쪽을 택할지, 상호 시야 구간을 몇 개 둘지, 각 구간의 교전 거리. CT 소폭 우세 요구와 직결되므로 임의로 정하지 않습니다. 위 측정값은 후보 A가 **가능하다**는 근거이지 채택 결정이 아닙니다.
- 검증: `VISION_ZONE_SIGHT_PAIRS`가 0보다 커지고 `DEPLOYMENT_ALL_OK`가 계속 나옵니다. `COMBAT_CASE_OK no-contact-no-damage`는 접촉이 생기는 순간 전제가 깨지므로 함께 고쳐야 합니다.

### 3단계 — 전투와 이동 연결

후퇴·로테이트·리테이크는 구현했습니다. 남은 것은 교전 그 자체의 세부입니다.

- **엄폐와 피킹.** 현재는 서로 마주 본 채 끝까지 쏩니다. 무빙 스탯이 여기서 들어갑니다. 피킹과 좌우 움직임은 2단계의 오차각 모델에 **이동 중 오차 배율**로 붙이면 그대로 연결됩니다.
- **트레이드.** 아군이 죽은 자리를 받아 치는 행동. 현재는 각자 가장 가까운 적만 봅니다.
- **침착함을 교전 판단에 사용.** 4절 기획대로 첫 적을 즉시 쏠지 후속을 기다릴지 결정합니다. 현재 침착함은 후퇴 판단에만 쓰입니다.
- **선수 간 충돌 회피.** 경로가 겹치면 서로 통과합니다.
- **미결정:** 재집결한 수비가 폭탄 설치 없이도 스스로 리테이크 타이밍을 잡을지. 지금은 설치를 기다립니다.
- 검증: `COMBAT_CASE_OK fairness`가 계속 50% 근처인지 확인합니다. 이동이 늘어나면 선후 처리 순서가 다시 승부를 왜곡하기 쉽습니다.

### 4단계 — 라운드 상태

한 라운드는 완결됩니다. 남은 것은 라운드를 이어 붙이는 층입니다.

- 라운드 점수, 9선승, 8:8 듀스, 정규 8라운드 후 공수 교대, 연장 매 라운드 교대.
- 타임아웃 팀당 2회, 타임아웃에서만 전술 변경.
- 라운드 간에 배치를 다시 지정하는 흐름. 현재는 `Reset / next seed`로 준비 상태로 돌아갑니다.
- 이 단계가 끝나야 "한 맵을 끝까지 진행"이 가능합니다.
- 검증: 한 맵 전체를 배치 모드로 돌려 승패가 규칙대로 결정되는지. 듀스와 공수 교대가 실제로 발생하는지 `behaviour-present`와 같은 방식으로 고정합니다.

### 5단계 — 구매와 경제

- 개별 가격표와 보상 전이표를 **먼저 정의**하고 고정 로드아웃에 연결합니다. 2단계의 `WeaponProfile`을 18종으로 확장하는 작업이 여기 포함됩니다.
- **미결정:** 4절에 남아 있는 항목 — 연속 승리 시 패배 보상 전이표 전체, 연장 공수 교대 시 생존 장비 처리, 개별 총기·방어구·유틸 가격.

### 6단계 — 전술·타임아웃

- 맵 시작 전 공수별 전술 설정, 타임아웃에서만 전술 변경, 역할·스탯에 따른 판단.
- IGL 카리스마 보너스(최대 +5 초안)의 계산식과 사망 시 유지 여부를 이때 확정합니다.

### 계속 미룰 것

- 그래픽, 애니메이션, UI 장식, 라디오 음성. 2절 작업 방식에 따라 더미를 유지합니다.
- 맵 지형 재설계. 0단계 참조.

## 8. GitHub에 저장할 것

- `Assets`와 그 안의 **`.meta` 파일**, `Packages`, `ProjectSettings`, README 및 `.gitignore`를 함께 관리합니다.
