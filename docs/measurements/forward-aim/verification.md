# 전진 수비 시야 수정 (2026-09-19)

## 원인

- 전진 명령의 `watch`가 `destination - position`이었다. 도착하면 영벡터가 되고, 조금 지나치면 돌아온 방향을 가리켰다. 다섯 공개 맵이 같은 명령 코드를 사용한다.
- 전진 명령은 `Patrol`이므로 사전 조준에서 정지 수비로 취급되지 않았다. 도착 직전의 경로 조준점 캐시도 계속 재사용할 수 있었다.
- 공개 맵의 가려진 조준점 보정은 첫 NAV 중심점이 가려지면 탐색을 중단했다. 뒤쪽 중심점을 선택하거나 자신의 위치를 반환할 수 있었으며, 후보 판정과 실제 시야 판정의 높이 기준도 달랐다. 버티고에서 실제 지형 시야 검사가 실패하는 사례를 재현했다.

## 수정

- 사이트에서 공격 진입로로 이어지는 NAV 경로를 따라 전진 위치보다 더 먼 감시 지점을 지정한다. 미드는 공격팀 스폰 방향의 NAV 경로를 사용한다. 적의 실제 위치를 입력하지 않는다.
- 전진 위치 3m 이내에서는 경로 대신 감시 지점을 조준한다. 이동/감시 상태, 임무, 감시 방향이 바뀌거나 조준점에 가까워지면 캐시를 갱신한다.
- 벽 뒤 조준점은 앞쪽의 실제 보이는 경로 지점으로 보정한다. 시작 NAV 중심점에 막혀도 다른 후보를 검사하며, 후보가 없으면 전방 부채꼴에서 보이는 방향을 찾는다. 후보 시야 검사는 게임의 시야 판정과 같은 함수를 사용한다.

## 재현 및 검증

- 변경 전: 도착 전 캐시를 유지하는 회귀 검사 실패 (`forward arrival kept cached destination instead of watching the approach`).
- 감시 지점/도착 처리만 수정한 중간 상태: 버티고 벽 시야 검사 실패 (`de_vertigo aims through wall`). 가려진 조준점 보정을 수정한 뒤 다섯 맵 모두 통과했다.
- `ForwardAimChecks.Run`: 도착/초과 이동, 버티고·인페르노·더스트2·미라지·뉴크의 실제 지형, 맵마다 전진 수비 4명, 벽 차단/전방 방향, 60/144 FPS 실제 회전, 해당 시야로 진입한 적 인지를 확인한다.
- `Tools/RunChecks.cs`에 새 검사를 등록했다.
- 설치된 Unity 6000.6.0f1의 실제 UnityEngine/UnityEditor 어셈블리에 대해 전체 게임·에디터 스크립트 컴파일 성공. 기존 obsolete/unused 경고만 있었다.
- 렌더링 화면의 수동 플레이 검증이나 새 실행 파일 빌드는 수행하지 않았다.

`forward.log`는 다섯 맵 모두 `FORWARD_AIM_MAP_OK` 및 `FORWARD_AIM_ALL_OK`로 종료했다. 각 맵의 전진 수비 4명을 60/144 FPS에서 확인했다.

전체 검사 실행은 장시간 반복 구간을 포함하므로 중단하고 관련 검사로 범위를 좁혔다. 전체 회귀 통과를 의미하지 않는다. `regression-interrupted.log`는 중단된 실행이며, `focused.log`는 이동 조준·표적 선택·전술·위협 대응·사전 조준·CT 개막의 여섯 검사 결과다.

최종 결과: 새 `ForwardAimChecks`와 기존 `MovementAimChecks`, `EngagementFocusChecks`, `SideTacticChecks`, `ThreatChecks`, `PreAimChecks`, `CtOpeningChecks` 총 일곱 묶음 통과. 관련 검사 로그는 `FOCUSED_FAILURES=0`으로 종료했다. 사전 조준 검사는 자연 경기 두 라운드를 완료했으며, CT 개막 검사는 뉴크 60/144 FPS 모두 통과했다. 검사한 여섯 소스/검사 등록 파일과 실제 D 드라이브 프로젝트 파일의 해시 일치 및 `git diff --check`도 확인했다.
